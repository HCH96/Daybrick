# L04 · 2026-11-11 · 수정: 테스트 방식 변경

- 요구사항: 전체
- 한 일: 기능마다 사람이 돌리던 사용자 체크리스트(2~3시간)를 없앴다. 대신 AI가 브라우저 미리보기로 화면을 확인하고, 사람은 출시 때 실제 환경만 확인한다.
  - 미리보기 예시 데이터: `apps/desktop/src/dev/`에 previewStore(개발 모드·Tauri 밖에서 localStorage 저장)와 fixtures를 만들었다. `?fixture=basic`·`empty`로 시작한다. 저장 함수 4곳(지원 관리·캘린더·플랜·투데이)과 서버 설정의 Tauri 밖 분기만 고쳤다.
  - 화면 확인 에이전트: `.claude/agents/test-ui.md`
  - `/test` 개편: 주체를 AI 코드 / AI 화면 / 출시 확인으로 나눴다.
  - 출시 확인 목록: `docs/desktop/common/human/release-check.md`. 출시 절차(desktop-release.md)에 확인 단계를 넣었다.
  - 테스트 방식 설명: `docs/desktop/common/ai/testing.md`
- 결정: AI 코드·AI 화면 항목을 통과하면 기능 완료다. 출시 확인 항목은 상태 칸에 "(출시 확인 N개)"만 붙인다. "사용자 테스트 생략" 메모리는 이 규칙으로 대신해서 지웠다.
- 계획과 달라진 점:
  - 시험 실행에서 나온 세 가지를 고쳤다.
    - empty 예시에서도 첫 실행 안내를 넘긴다.
    - 팝업은 본문 밖이라 `find`로 읽는다는 규칙을 넣었다.
    - 이전 콘솔 오류는 빼고 새 오류만 본다는 규칙을 넣었다.
  - 새 에이전트 정의는 다음 세션부터 잡혀서, 시험 실행은 일반 에이전트에 정의를 따르게 해서 돌렸다.
- 확인 (실제로 실행함):
  - 하위 에이전트가 내장 브라우저를 쓸 수 있음.
  - `?fixture=basic`으로 홈·지원 관리에 예시가 채워지고 localStorage에 5종류가 저장됨. `?fixture=empty`로 빈 홈이 뜸.
  - 출시 빌드(dist)에 예시 데이터·미리보기 저장소 문자열이 없음.
  - 시험 실행(투데이 5항목) 통과 5. 하위 에이전트 호출 20회, 캐시 읽기 약 122만.
  - `npx tsc --noEmit`, `npm run build`, 링크 검사 통과.
  - Tauri 앱(`tauri dev`)으로 띄워 확인하지는 않았다. Tauri 분기는 같은 동작으로 바꾼 것을 변경 내용과 빌드로 확인했다.
- 남은 문제:
  - 기존 대기 중인 사용자 체크리스트(human/tests/)에서 실제 환경 항목을 출시 확인 목록으로 옮기는 일은 하지 않았다.
  - 개발 중 핫 리로드 꼬임으로 "usePlan은 PlanProvider 안에서만" 오류가 났다. 개발 서버를 다시 시작하니 사라졌다.

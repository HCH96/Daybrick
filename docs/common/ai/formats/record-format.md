# 진행 기록·결정 양식
모든 명령(/spec, /mockup, /plan, /implement, /test)과 명령 없이 하는 작업이 기록과 결정을 남길 때 따르는 양식. 형식을 보려고 예전 기록 파일(LNN.md)을 읽지 않는다.

## 진행 기록 쓰는 법
폴더: docs/<플랫폼>/features/<기능명>/ai/logs/ (특정 기능에 속하지 않는 공용 작업은 docs/common/ai/logs/, 결정은 CLAUDE.md에 바로 반영)
- index.md: 기록 목차 하나. 항목을 추가하면 같은 작업에서 한 줄 추가한다.
- LNN.md: 기록 항목 하나당 파일 하나 (L01.md, L02.md …).

index.md:
```markdown
# <기능 이름> (<기능명>) 진행 기록 목차
항목 하나당 파일 하나(`L번호.md`). 필요한 항목 파일만 읽는다.

| ID | 날짜 | 종류 | 요구사항 | 내용 |
|---|---|---|---|---|
| [L08](L08.md) | 2026-10-23 | 구현 | R17–R22 | 5단계: 상태 (최종 테스트 대기) |
```

LNN.md:
```markdown
# L08 · 2026-10-23 · 구현 5단계: 상태

- 요구사항: R17–R22
- 한 일: (3~6줄)
- 결정: D6 추가 (있을 때만)
- 계획과 달라진 점: (있을 때만, "(자동 진행 중 판단)" 또는 사용자 승인 여부 포함)
- 확인: 빌드·타입 검사 결과 (1~3줄, 실제로 실행한 것만)
- 사용자 확인: 완료 / 대기 (최종 테스트)
- 테스트 메모: (있을 때만, 1~2줄)
- 남은 문제: (있을 때만)
- 주요 파일: 핵심 파일 몇 개만
```

- 종류: 명세 / 목업 / 계획 / 구현 / 테스트 / 수정
- ID: 기능 안에서 L01부터 차례로 붙인다. 한 번 붙인 번호는 바꾸지 않는다. (보관 폴더로 옮긴 옛 기록이 있으면 그 다음 번호부터 이어 간다.)
- 요구사항: R 번호. 기능 전체에 걸친 항목은 "전체".
- 테스트 메모: 테스트 항목은 /test가 명세서와 step 파일의 "확인할 결과"로 한 번에 만든다. 여기에는 문서만 봐서는 알 수 없는 확인거리만 적는다 (예: "긴 제목은 말줄임 처리 → 30자 넘는 제목 확인", "일정 없는 달은 빈 칸"). 계획대로라 더할 게 없으면 줄을 쓰지 않는다.
- 항목 본문은 30줄 이내로 쓴다. 파일마다 넣은 함수·CSS 값 같은 세부 목록, 계획 문서에 이미 있는 내용의 반복("step-05대로"로 충분)은 쓰지 않는다. 앞으로 지킬 내용은 결정으로 decisions.md에 올린다.

## 결정 올리기
앞으로의 작업에서도 지켜야 할 결정(구조, 규칙, 계획과 달라진 방식, 개발 환경 주의점 등)은 기록에만 두지 않는다.

- ai/spec/decisions.md에 번호를 붙여 올린다:
  `- D6. 내용 (적용: 5~7단계 / 이후 전체) (기록: L08)`
- 적용 범위는 계획 색인(ai/plan/index.md)의 단계 표를 보고 정한다. 확실하지 않으면 "이후 전체"로 적는다.
- 결정이 바뀌면 지우지 않고 줄을 고친 뒤 끝에 "(L번호에서 변경)"을 붙인다.
- 기록 항목의 "결정" 줄에 D 번호를 적어 서로 이어지게 한다.

# 구직 관리 (job-search) 사용자 테스트 체크리스트 r3
- 작성일: 2026-10-30 · 범위: 수정2(직군 거르기·일괄 처리·묶기 확장·출처 표시)의 주요 기능만 (사용자 요청으로 간단하게. 세부 규칙은 AI 테스트에서 확인)
- 근거: 테스트 계획 r3 (U1–U17), AI 테스트 보고서 [../../ai/tests/r3/](../../ai/tests/r3/)
- 화면은 AI가 직접 보지 않았다. 예상 결과는 명세·진행 기록·화면 문구 기준이다.

## 이번 회차 범위
- 대상 R: R8, R40, R41, R47, R48, R73, R74, R91–R115
- 영향받는 R: R4, R7, R9, R16, R23, R33, R46, R53, R75, R80, R83–R89
- 다시 하는 이전 항목: r2 6번(보류), r2 7–14번(판정 비어 있음)
- 재등록 묶기(R111–R112)·애매한 쌍(R113–R115)은 실제 데이터에 없을 수 있어 AI 테스트에서만 확인한다.

## 준비
1. 테스트용 Supabase·Anthropic 키로 연결된 앱을 `npm run tauri dev`로 켠다.
2. **업데이트 전 기록 (옛 데이터 백업):** 서버 업데이트 전에 SQL 편집기에서 `select stage, count(*) from js_postings group by stage`를 실행해 결과를 메모한다. 서버 업데이트가 `js_postings_backup_0008` 표에 공고를 자동으로 백업하지만, 걱정되면 Table Editor에서 `js_postings`를 CSV로 내려받아 둔다.
3. 업데이트 전 추천 목록에서 **아트·기획 계열 공고**(제목에 원화·모델러·애니메이터·기획 등)가 있는지 찾아 회사·제목·점수를 하나 적어 둔다 → 이후 "공고 P". 없으면 U2는 "해당 없음"으로 적는다.
4. r2에서 만든 "게임잡 자사" 사이트(게임잡과 같은 주소, 자사 체크 켬)가 남아 있어야 한다. 없으면 수집 사이트 탭 [사이트 추가]로 다시 만든다 (이름 "게임잡 자사", 주소·어댑터는 게임잡과 같게, 자사 체크 켬 → [시험 수집] → [저장]).
5. 이후 "묶음 공고"는 상세 팝업 제목 아래 출처 칩이 2개 이상인 공고를 뜻한다 (카드에는 출처가 보이지 않는다).
6. 일괄 처리는 결과가 오기까지 몇 분~최대 24시간 걸린다. U3 → U4는 기다리는 시간이 필요하므로, U3 뒤 U6–U8 등을 먼저 해도 된다.

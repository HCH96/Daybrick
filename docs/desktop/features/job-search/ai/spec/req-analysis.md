# 구직 관리 요구사항: 필터·항목 추출·적합도 채점 (R41–R53, R94–R101)

### 처리 순서
- R41. 공고는 "1차 필터 → 항목 추출(직군 포함) → 중복 확인(R83) → 2차 필터 → 적합도 채점" 순서로 처리하고, 앞 단계에서 걸러지거나 묶인 공고는 다음 단계로 가지 않는다. 주간 처리에서는 추출과 채점을 일괄 처리(R102)로 한다. (L44에서 변경)

| 단계 | AI | 판단 근거 |
|---|---|---|
| 1차 필터 | 없음 | 목록 정보(제목·회사·직무) |
| 항목 추출 + 직군 + 인젝션 검사 | Haiku 5.5 (일괄) | 원문 |
| 중복 확인 | 애매한 쌍만 Haiku 5.5 (바로 호출, R113) | 추출 항목 + 정리한 회사·제목 ([req-dedupe.md](req-dedupe.md)) |
| 2차 필터 | 없음 | 추출 항목(직군 포함) |
| 적합도 채점 | Opus 5.5 (일괄) | 프로필 + 추출 항목 |

### 필터
- R42. 1차 필터 조건: 제목·직무 키워드 포함/제외, 회사 제외.
- R43. 2차 필터 조건: 기술스택 포함/제외, 경력 연수(예: N년 이상 요구 제외), 고용 형태.
- R44. 기술스택 자동 추림: 프로필 기술스택과 공고 기술스택이 하나도 겹치지 않으면 걸러낸다. 켜고 끌 수 있다.
- R45. 필터 탭에서 조건을 추가·삭제하고 켜고 끈다. 켜진 조건은 모두 만족해야 통과한다.
- R46. 걸러진 공고는 "걸러진 공고" 목록에서 걸린 조건과 함께 보고, 하나씩 "그래도 채점"할 수 있다.
- R47. 필터를 바꾸면 아직 채점하지 않은 공고에만 다시 적용하고, 이미 채점한 결과는 그대로 둔다. 예외는 직군 거르기(R99)다. (L44에서 변경)

### 항목 추출
- R48. 추출 항목: 직무, 직군(R97), 자격 요건, 우대사항, 기술스택, 경력 연수, 고용 형태, 근무지, 지원 마감일, 전형 일정(과제 마감·코딩테스트·면접 날짜). (L44에서 변경)
- R49. 추출과 함께 프롬프트 인젝션 검사를 한다. 의심 공고는 표시하고 채점으로 보내지 않으며, 사용자가 "그래도 채점"을 누르면 진행한다.
- R50. 원문에 없는 항목은 비운다. 날짜는 정리한 값과 원문 표기를 함께 저장한다.

### 적합도 채점
- R51. 채점 결과: 0–100점, 등급, 강점, 부족한 점(각각 근거 포함), 한 줄 요약.
- R52. 채점 기준과 작성 규칙은 [ai-rules.md](ai-rules.md)를 따른다.
- R53. 추출·채점 결과는 저장해 재사용하고, 같은 공고를 같은 프로필로 다시 호출하지 않는다.

### 처리 흐름 줄 (필터 탭)
- R94. 필터 탭의 처리 흐름 줄은 이번 주에 수집한 공고를 모든 처리 단계(묶임·실패 포함)로 읽고, 단계 하나 때문에 전체를 읽지 못한 것으로 처리하지 않는다.
- R95. 처리 흐름 줄에 "중복으로 묶음 N개"를 따로 보여준다.

### 직군 거르기 (개발 직군만)
- R96. 1차 필터에 기본 조건 "비개발 직군 낱말"을 둔다. 제목·직무에 아트·기획 계열 낱말(모델러, 원화, 애니메이터, 이펙트, 테크니컬 아티스트, 테크니컬 디자이너, 기획 등)이 있으면 거른다. 같은 제목에 개발 낱말(프로그래머·개발·엔지니어)이 함께 있으면 1차에서는 거르지 않고 R97에 맡긴다. 낱말은 필터 탭에서 고칠 수 있다.
- R97. 항목 추출 때 직군을 하나 고른다: 개발 / 아트 / 기획 / QA / 사업·운영 / 기타 / 판단 불가. 개발로 보는 범위는 D65를 따른다.
- R98. 2차 필터에 "개발 직군만" 조건을 두고 기본으로 켠다. 직군이 개발이 아니면 거르고, 걸린 조건은 "직군: 아트"처럼 보인다.
- R99. 이미 채점된 공고도 직군이 개발이 아니면 걸러진 공고로 옮긴다. 점수는 지우지 않고, [그래도 채점]으로 추천에 되돌릴 수 있다.
- R100. 서버 업데이트 뒤 한 번, 직군이 없는 기존 공고(추출만 된 공고, 채점된 공고)는 제목·직무·추출 항목으로 직군만 짧게 물어 채운다.
- R101. 직군이 "판단 불가"인 공고는 거르지 않고 통과시킨다.

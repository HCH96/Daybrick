# L67 · 2026-11-11 · 수정: 목록으로만 본문을 받는 사이트에서 빈 원문이 저장되는 문제

- 요구사항: R39, R48 (영향: R50)
- 한 일: 10/29에 수집한 시프트업 공고 41개의 원문이 빈 글자(`""`)로 저장돼, 제목만으로 추출·채점됐다(직무·직군 말고 항목이 모두 빔). 시프트업 규칙은 상세 규칙 없이 목록의 `content`로만 본문을 받는다. 목록 본문을 그 실행에서 저장하지 못하면 다음 실행의 `fetchBodies`가 `readDetail`로 넘어가는데, 상세 규칙이 없으면 `readDetail`은 실패가 아니라 빈 본문을 돌려줘 그대로 저장됐다. 원문 없음은 `null`로만 판단하므로 빈 글자로 저장된 공고는 D90 뒤에도 다시 채워지지 않았다. 지금 시프트업 목록은 모든 공고에 본문을 준다(직접 받아 확인).
  - `fetchBodies`: 이번 목록 본문이 없고 상세 규칙도 없으면 저장하지 않고 넘어가 `null`로 둔다. 다음 수집이 목록 본문으로 채운다(D90).
  - 서버 데이터: 시프트업 공고 중 원문이 빈 글자이고 이미지가 없는 공고의 원문을 `null`로 되돌렸다. 묶인 공고가 아닌 공고는 추출·채점 결과를 지우고 단계를 `new`로 돌려 다시 처리되게 했다(사용자 승인).
  - 넷마블·크래프톤에도 원문이 빈 공고 6개가 있다. 이 사이트들은 상세 규칙이 있어 원인이 다르다. 넷마블 1887은 상세 API가 본문을 비워 준다(직접 확인). 그대로 둔다.

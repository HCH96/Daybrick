# L41 · 2026-10-29 · 구현 수정1 7단계: 상세 팝업 출처·따로 보기

- 요구사항: R92, R93 (영향: R55)
- 한 일: step-07대로 `bundleApi.ts`에 `unbundlePosting`(rpc `js_unbundle`, 새 대표 id 또는 null)을 더하고, `loadPostingDetail`이 출처를 함께 읽어 `PostingDetail.sources`로 넘긴다. 새 `PopupSources`가 팝업 머리 칩 줄 아래에 "출처" 블록(사이트 이름 ↗ — 기존 `openExternal`로 열기, 대표 줄 "(대표)", 줄마다 [따로 보기])을 그린다. [따로 보기]는 확인 없이 실행하고, 대표를 풀면 팝업을 닫고 묶인 공고를 풀면 "따로 볼게요. 다음 처리 뒤 별도 공고로 보여요."를 보인 뒤 팝업을 다시 읽는다(둘 다 `onChanged`). 지원한 공고는 [따로 보기]를 끈다. 묶음 대표의 원문이 아직 없으면 "원문을 받는 중이에요. 다음 수집 처리 뒤 보여요."를 보인다. [지원하기]는 팝업 공고(대표) 링크를 그대로 쓴다(코드 변경 없음).
- 결정: D63 추가
- 계획과 달라진 점: (자동 진행 중 판단) 출처 블록은 `PopupHead`에 `sources` 자리(ReactNode)를 두어 머리 안 칩 줄 아래에 넣었다(점수 상자 위라는 계획 위치와 같음). [따로 보기] 중 아래 단추를 끄려고 `PopupFoot`의 `FootBusy`에 `"unbundle"`을 더했다(step 파일 목록 밖, `PopupFoot.tsx`).
- 확인: `npm run build`(tsc 포함) 통과. 서버에 붙여 실제로 풀어 보지는 않음(/test로 넘김).
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 링크가 없는 출처는 ↗가 꺼져 있다. 출처 읽기가 실패하면 팝업 전체가 읽기 실패로 보인다.

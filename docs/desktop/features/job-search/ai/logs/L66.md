# L66 · 2026-11-11 · 수정: 확장자와 실제 형식이 다른 이미지를 Anthropic이 거절하는 문제

- 요구사항: R38, R48
- 한 일: L65 배포 뒤 추출 일괄에서 공고 1개가 "image/png로 보냈지만 실제로는 image/jpeg"로 거절돼 failed가 됨.
  수집(`js-collect`)은 사이트가 알려 준 Content-Type으로 저장 이름의 확장자를 정하고, 추출 요청(`attach.ts`)은 그 확장자로 media type을 정했음. 사이트 정보가 틀리면 JPEG·PNG·WebP 어느 쪽이든 같은 문제가 남.
  `imagePdf.ts`에 파일 앞부분으로 형식을 읽는 `sniffImageType`을 더하고, `attach.ts`가 확장자 대신 이것으로 media type을 정하게 함. 이미지가 아닌 파일(예: 오류 페이지)은 빼고 로그에 남김. PDF로 바꾸는 쪽은 원래 파일 내용으로 형식을 봄.
  이미 저장된 파일에도 적용되도록 저장할 때가 아니라 읽을 때 고침.
- 확인: Node로 JPEG를 .png로·PNG를 .jpg로·WebP를 .jpg로·HTML을 .png로 둔 경우를 실행해 실제 형식으로 나가고 HTML은 빠짐. L64·L65 확인 스크립트도 다시 통과.

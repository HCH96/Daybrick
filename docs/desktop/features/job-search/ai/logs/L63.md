# L63 · 2026-11-09 · 수정: Gmail 연결 상태 보기를 security invoker로 (서버 구조 11번)

- 요구사항: R60, R70
- 한 일: Supabase Security Advisor가 `js_gmail_status`를 "Security Definer View"(CRITICAL)로 표시함 (본인 행 조건이 있어 실제 노출 위험은 낮았음).
  새 마이그레이션 0011에서 `js_gmail_tokens`에 토큰이 아닌 열(user_id, email, last_checked_at, broken_at)만 열 단위 select 권한과 본인 행 select 정책을 주고,
  보기를 `security_invoker = true`로 바꿈. 보기 모양은 같아 앱 읽기 코드(gmailApi.ts)는 그대로. 쓰기와 토큰 열(cipher, iv)은 계속 서비스 역할만.
  migrations.rs에 11번 추가, 미리보기 서버 구조 번호 5 → 11 (data-sync가 10번 때 못 올린 값도 함께 바로잡음).
- 결정: D91 추가, D14 일부 변경
- 계획과 달라진 점: 두 방법(invoker 보기 / security definer RPC) 비교 뒤 invoker 보기로 (사용자 승인). RPC는 Advisor가 실행 가능한 definer 함수로 다시 경고할 수 있어 뺌.
- 확인: `npm run build` 성공(500kB 청크 경고만), `cargo check` 성공. 서버 적용·Advisor 결과는 아직 실행해 보지 않음.
- 사용자 확인: 대기 (서버 업데이트 뒤 Advisor 경고 사라짐, Gmail 연결 상태 그대로 보임)
- 테스트 메모: SQL Editor에서 `select has_column_privilege('authenticated','public.js_gmail_tokens','cipher','select');` → false
- 주요 파일: supabase/migrations/0011_job_search_gmail_status.sql, apps/desktop/src-tauri/src/server/migrations.rs

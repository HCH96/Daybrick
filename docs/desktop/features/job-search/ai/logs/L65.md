# L65 · 2026-11-11 · 수정: 투명 이미지 풀기가 함수 CPU 한도를 넘는 문제

- 요구사항: R38, R102, R106
- 한 일: L64를 CLI로 배포한 뒤(공용 기록 L14) 10:52 UTC 예약 처리가 이번에는 `CPU Time exceeded`(546)로 실패함. 메모리 초과는 사라짐.
  투명 PNG를 한 픽셀씩 흰 바탕에 합치는 데 개발 PC 기준 1픽셀에 약 0.14µs가 들어, 큰 투명 이미지 한 장으로 함수 CPU 한도 2초를 다 씀.
  실행 한 번에 풀 수 있는 투명 픽셀 합계를 400만(약 0.55초)으로 정하고(`ALPHA_RUN_PIXELS`, 실행마다 `Context.alphaLeft`로 시작),
  이미 몫을 쓴 실행에서 모자라면 그 공고는 맡기지 않고 다음 실행으로(`extractRequest`가 null, 바로 호출은 time 멈춤), 처음 쓰는 공고인데도 넘치면 들어가는 이미지만 풀고 나머지는 뺌(로그). 풀지 않아도 보낼 수 있는 이미지는 이미지 블록으로.
- 결정: D92 추가
- 계획과 달라진 점: 사용자 승인은 600만 픽셀이었으나, 측정해 보니 1픽셀 비용이 예상의 1.4배라 여유를 두려고 400만으로 낮춤 (보고에 알림)
- 확인: Node로 첨부 만들기 6가지(새 몫·몫 모자람·한 장이 몫 초과·두 장·짧은 투명·투명 없음) 실행해 기대대로 나옴, 옛·새 PNG 결과 비교 같음.
  js-process 전체 tsc 타입 검사(Deno 모듈은 임시 선언) 통과, `npm run build` 성공, `npm test` 39개 통과, `cargo check` 성공.
- 사용자 확인: 대기 (CLI 배포 뒤 예약 처리·[지금 평가] 성공, 출시 확인 C1)
- 남은 문제: 몫 때문에 뺀 이미지에만 있는 내용은 그 공고 추출에서 빠질 수 있음

# 백그라운드 실행 결정 사항

- D1. 닫기·종료의 판단은 프론트(React)가 한다. Rust는 창의 닫기 요청을 막고 `daybrick://close-requested`를, 트레이 "종료"는 `daybrick://quit-requested`를 보내기만 한다. 안내·확인·저장 뒤 프론트가 `hide_main_window`·`quit_app`을 부른다. (적용: 2단계 이후 전체) (기록: L02)
- D2. 종료 요청 뒤 3초 안에 프론트가 `ack_quit_request`를 부르지 않으면(화면이 멈춤 등) Rust가 바로 끈다. 앱을 끌 수 없는 상태를 막기 위해서다. (적용: 2단계 이후 전체) (기록: L02)
- D3. 종료 전 저장(`runQuitHandlers`)은 전부 합쳐 최대 5초까지만 기다리고, 시간이 지나도 종료한다 (동기화 D13의 로컬 1초 + 올리기 3초 위에 여유를 둠). (적용: 2단계 이후 전체) (기록: L02)
- D4. 종료 전 저장은 `app/quit.ts`의 `onQuitRequested`에 등록한다. 창은 숨기기만 하므로 기능은 `onCloseRequested`를 쓰지 않는다 (앞으로 새 기능도 같음). (적용: 2단계 이후 전체) (기록: L02)
- D5. 첫 실행 자동 시작 등록은 성공했을 때만 `app-settings.json`의 `autostartInitialized`를 true로 적는다. 실패하면 다음 실행 때 다시 시도한다. 한 번 true가 되면 사용자가 끈 상태를 다시 켜지 않는다. (적용: 4단계 이후 전체) (기록: L02)
- D6. 개발 모드(`cfg!(debug_assertions)`)에서는 자동 시작을 등록·해제하지 않고, 설정 스위치를 비활성으로 두고 "개발 모드에서는 바꿀 수 없어요"를 보여 준다. (적용: 4단계 이후 전체) (기록: L02)
- D7. 메인 창은 `visible: false`로 만들고, setup에서 `--autostart` 인자가 없을 때만 보여 준다. 자동 시작 때 창이 번쩍이지 않게 하기 위해서다. (적용: 4단계 이후 전체) (기록: L02)

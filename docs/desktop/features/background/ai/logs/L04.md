# L04 · 2026-11-09 · 구현 2단계: 닫기와 종료 나누기

- 요구사항: R1, R2, R3, R5, R9, R11, R12
- 한 일: Rust `background/mod.rs`에 `on_window_event`(main 창 `CloseRequested`를 막고 `daybrick://close-requested`)를 두고, 새 `quit.rs`에 `request_quit`(요청 번호를 두고 3초 감시, D2)과 명령 `show_main_window`·`hide_main_window`·`quit_app`·`ack_quit_request`를 넣었다. 트레이 "종료"는 `request_quit`로 바꿨다.
- 프론트: 새 `app/quit.ts`(등록소, 모두 allSettled·최대 5초), `features/background/api.ts`, `BackgroundProvider.tsx`(닫기 → 숨기기, 종료 → 응답 → 저장 → 끄기, 종료 진행 중 다시 온 요청은 응답만). 다섯 `useAutoSave.ts`를 `onQuitRequested`로 바꾸고(처리기 본문 그대로) 주석을 "종료" 기준으로 고쳤다. `useCloseFlush.ts`는 주석만.
- 계획과 달라진 점: `BackgroundProvider`는 형제 컴포넌트가 아니라 `TodayProvider` 안의 내용을 children으로 감싼다 (3단계에서 안내·확인 창 상태를 context로 내주기 위함) (자동 진행 중 판단).
- 확인: `cargo check` 성공(경고 없음), `npm run build`(tsc 포함) 성공. `grep -rn onCloseRequested src` 결과 없음. 앱을 띄워 보는 확인은 하지 않음.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 트레이 "종료"를 빠르게 두 번 눌러도 저장이 한 번만 돌고 정상 종료되는지.
- 남은 문제: `useCloseFlush`의 올리기 묶음(sessionRef)은 한 번 만들면 비우지 않는다. 3단계에서 종료를 [취소]할 수 있게 되면, 다음 종료 때 올리기를 다시 시도하지 않는다.
- 주요 파일: `apps/desktop/src-tauri/src/background/quit.rs`, `background/mod.rs`, `src/app/quit.ts`, `src/features/background/BackgroundProvider.tsx`

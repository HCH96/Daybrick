# 지원 관리: 다룰 데이터

**지원 (카드 하나)**
| 항목 | 설명 |
|---|---|
| id | 고유 번호 |
| 제목 | 텍스트, 비어 있을 수 있음 |
| 상태 | 지원 준비 / 지원 완료 / 전형 준비 / 결과 대기 / 종료 |
| 세부 단계 | 전형 준비·결과 대기일 때만: 과제 / 코딩테스트 / 면접 |
| 속성 값 | 속성 id별 값, 기본은 없음 |
| 전형 일정 목록 | 아래 "전형 일정" 여러 개 |
| 본문 | 마크다운 텍스트 |
| 만든 날, 고친 날 | 날짜·시간 |

**전형 일정**: 종류(지원 마감 / 과제 마감 / 코딩테스트 / 면접), 날짜, 시간(선택), 메모(선택). 지원 마감은 카드당 하나 (R39). (L18에서 변경: "지원 완료" 종류 없앰)

**속성 정의 (모든 카드가 공유)**: id, 이름, 종류(7가지), 순서, 선택 항목 목록(항목 이름 + 색), 기본 속성 여부

**기본 속성**
| 속성 | 종류 | 처음 들어 있는 항목 |
|---|---|---|
| 결과 | 선택 | 최종 합격 / 불합격 / 지원 포기 |
| 회사 | 선택 | 없음 (쓰면서 추가) |
| 직무 | 선택 | 없음 (쓰면서 추가) |
| 공고 링크 | URL | - |
| 우선순위 | 선택 | 높음 / 중간 / 낮음 |
| 제출 자료 | 다중 선택 | 이력서 / 자기소개서 / 포트폴리오 PDF / 포트폴리오 Notion / 기술 소개서 / GitHub / 과제 결과물 |
| 경력 구분 | 선택 | 신입 / 경력 / 무관 |
| 고용 형태 | 선택 | 정규직 / 계약직 / 인턴 / 전환형 인턴 |

마감일·지원일 기본 속성은 L18에서 없앰 (R40).

**저장 위치**: 이번에는 PC에만 저장한다(개발 순서 1단계). 붙여 넣은 이미지는 앱 데이터 폴더에 파일로 저장한다. 구체적인 저장 방식은 구현 계획에서 정한다.

**상태 색**: 홈에서 쓰는 색(회색·파랑·주황·초록)을 이어서 쓴다. 상태별 색 배정은 목업에서 정한다. (→ 정함, [mockup.md](mockup.md) "목업에서 정한 것" 참고)

# 프로젝트 (projects) 결정 사항

- D1. 카테고리 상세 페이지는 만들지 않고 프로젝트 페이지로 합친다. 개발일지는 별도 기록이 아니라 태스크 메모를 쓴다 (플랜 scope.md의 "개발일지는 카테고리·날짜에 묶인 별도 기록" 메모를 대체) (적용: 이후 전체) (기록: L01)
- D2. 태스크는 카테고리 하나 또는 프로젝트 단계 하나에만 속한다. 플랜 태스크 데이터에 단계 id를 더한다 (적용: 이후 전체) (기록: L01)
- D3. 진행률·끝난 단계·현재 단계·프로젝트 완료·시간 합계는 저장하지 않고 계산한다 (적용: 이후 전체) (기록: L01)
- D4. "작업한 날"은 프로젝트 태스크에 시간 기록이 1분이라도 있는 날로, 마지막 작업일·카드 모닥불·잔디·연속 작업일이 모두 같은 기준을 쓴다. 투데이의 스트릭(하루 목표를 채운 날)과는 다른 값이다 (적용: 이후 전체) (기록: L02)
- D5. 프로젝트·단계는 plan.json에 함께 둔다. 단계는 프로젝트 안 stages[](순서 = 배열 순서), 태스크에 stageId를 더한다. 프로젝트·단계 삭제와 태스크 옮기기는 reducer 한 번으로 처리한다 (적용: 이후 전체) (기록: L03)
- D6. 저장 파일은 옮기지 않는다. plan.json version 1 그대로, 읽을 때 없는 값(projects, stageId, stageFold, projectsDoneOpen)을 빈 값으로 채운다 (적용: 이후 전체) (기록: L03)
- D7. 앱 방문 기록 한 칸을 { page, sub? }로 바꿔, 프로젝트 상세(sub = 프로젝트 id)도 앱 공용 뒤로가기로 오간다. 기존 navigate(page) 호출은 그대로 둔다 (적용: 3단계 이후) (기록: L03)
- D8. 버블 그래프는 d3-force·d3-ease(+ 타입 패키지)를 설치해 시안 값을 그대로 쓴다 (적용: 6–7단계) (기록: L03)
- D9. 프로젝트 시간 값은 10초마다 확인하고 분 단위 값이 바뀔 때만 다시 그린다. 버블 튀기·잔디 진하기 오름도 그 순간에 나온다 (적용: 2단계 이후) (기록: L03)
- D10. 없는 단계를 가리키는 태스크(stageId가 남았지만 그 단계가 없음)는 플랜에서 미분류로 보이게 한다. 플랜 묶음은 `knownStageIds`로 있는 단계 태스크만 뺀다 (적용: 이후 전체) (기록: L04)
- D11. 프로젝트 만들기 입력은 종류별 유니온 `NewProject`(단계형 `stageNames` / 주차형 `startWeek`·`weekCount`·`weekNames?`)로 store `addProject`에 넘긴다. 시간 계산 값은 투데이와 같이 밀리초다 (적용: 2단계 이후) (기록: L04)
- D12. 프로젝트 색 고르기(기본 색 7개 + `직접 고르기` = 플랜 ColorPicker)는 `pages/projects/create/ColorChoice.tsx` 하나를 만들기 창·이름·색 바꾸기·단계 편집 창이 같이 쓴다. 프로젝트 창의 버튼·입력칸·단계 줄 클래스(`proj-btn`·`proj-input`·`proj-step` 등)는 `create/Create.css`에 있다 (적용: 2단계 이후) (기록: L05)
- D13. 진행 중 카드는 카드 전체를 눌러 끈다(useReorder, 4px 넘게 움직여야 끌기, 끈 뒤 클릭은 막힘). 카드 클릭(상세 열기)은 카드 onClick으로 붙인다. 겹침 층 팝업에서 올라온 React 이벤트는 카드 DOM 안이 아니면 끌기로 보지 않는다 (적용: 2단계 이후) (기록: L05)
- D14. 상세 화면 CSS(머리 `proj-detail__*`, 진행 판 `proj-progress*`, 깃발 트랙 `proj-track*`·`proj-flag*`)는 `pages/projects/detail/Detail.css` 하나에 둔다. 상세의 `…` 메뉴는 `list/CardMenu`를 그대로 쓰고 `onDeleted`로 삭제 뒤 목록으로 간다. 프로젝트 색 `--c`는 `ProjectDetail` 맨 바깥에서 내려준다 (적용: 3단계 이후) (기록: L06)
- D15. 단계 칸의 태스크 줄·끌기는 플랜 `TaskRow`·`DragGhost`·`PlanDragProvider`를 쓰지 않고 `detail/StageTaskRow`·`useStageTaskDrag`(놓을 칸 `data-drop-stage`)로 따로 두되, 클래스는 플랜 것(`plan-task*`, `plan-drag-ghost--task`)을 그대로 쓴다. 그래서 `StageBoard`가 플랜 `list/TaskList.css`·`drag/drag.css`를 가져온다. 단계 칸 CSS(`proj-stages`·`proj-stage*`·`proj-stask`)는 `detail/Detail.css`에 둔다 (적용: 4단계 이후) (기록: L07)
- D16. 단계 편집 창 `edit/EditStagesDialog`는 props `project`·`onClose`만 받고 태스크는 store에서 읽어, 상세 머리와 카드 `…` 메뉴 어디서든 연다. 편집·확인 창 CSS는 `create/Create.css` + `edit/Edit.css`, 단계 삭제 확인 창은 공용 `ConfirmDialog.css` 클래스를 쓴다. 골인 연출은 `detail/GoalCelebration`의 `useGoalCelebration`(완료 + `goalSeenAt` 빈 값이면 한 번)이 `ProgressPanel` 안에서 정하고, CSS(`proj-goal*`, `proj-progress__track--goal`)는 `detail/Detail.css`에 둔다 (적용: 5단계 이후) (기록: L08)
- D17. 목록 윗줄 틀 CSS(`proj-top`·`proj-panel`·`proj-panel__head`·`proj-panel__right`·`proj-live`)는 `pages/projects/ProjectsPage.css`에 두고 잔디·버블 판이 같이 쓴다. 버블 판은 `top/BubblePanel`(props `data`·`clock`)이 그리고, 원 `<g>`의 위치·반지름·투명도는 `useBubbleSim`이 매 틱 DOM에 직접 쓴다(React는 원 안 글자·범례만). 버블 CSS(`proj-bubble*`)는 `top/Bubble.css` (적용: 6단계 이후) (기록: L09)
- D18. 잔디·칸 말풍선의 날짜별 시간은 `useProjectClock`의 `clock.days`(프로젝트 id → 날짜 → 밀리초, 분 단위 내림)를 쓰고, 같은 객체 비교(D9)에 이 값도 넣는다. 잔디 판은 `top/HeatPanel`(props `data`·`clock`·`highlight`·`onHoverDay`), 계산은 `features/projects/heat.ts`, CSS(`proj-heat*`·`proj-hs*`)는 `top/Heat.css`. 버블 원 `<g>`의 셋째 요소가 테두리 원(`proj-bubble__halo`, 흰 테두리·반짝임)이고 반지름은 `useBubbleSim`이 원 반지름 + 5로 쓴다. 흐림 0.3은 `<g>` 안 요소에 건다 (적용: 7단계 이후) (기록: L10)
- D19. 태스크 묶음 이름·색은 `features/projects/group.ts`의 `taskGroupInfo(data, task)`(kind `category`/`stage`/`none`, 단계는 name "<프로젝트> › <단계>"·`projectName`·프로젝트 색, 없는 단계·카테고리는 `NONE_GROUP_INFO`)로 얻는다. 같은 파일에 `projectStageName`·`findStage`·`splitStageTasks`·`projectFoldKey`(`project:<id>`, view.collapsed 키)가 있다. 플랜 트리 단계 묶음은 `list/StageGroup`(머리는 `plan-ghead plan-ghead--stage` 직접 그림, `data-drop-stage`), 프로젝트 묶음은 `list/ProjectGroup`(`GroupHead`에 `onAdd`·`onMenu`를 주지 않아 `+`·`…` 없음). 플랜 `BarLayer`는 `categories` 대신 `plan`(PlanData | null)을 받는다 (적용: 8단계 이후) (기록: L11)
- D20. 투데이 카드·타이머·미완료 팝업 줄의 묶음 이름·색은 `group.ts`의 `taskCardGroup(data, task)`(`CardGroup { name; color } | null`, 단계 태스크는 프로젝트 이름·색, 미분류는 null)로 얻고, 그 컴포넌트들의 `category` prop 타입은 `CardGroup | null`이다. 투데이 묶음별 합계 `categoryTotals(day, data: PlanData)`는 프로젝트 태스크를 id `project:<id>` 한 줄로 묶는다 (적용: 9단계 이후) (기록: L12)

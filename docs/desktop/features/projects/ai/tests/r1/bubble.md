# 주간 투입 버블 (req-bubble, A11·A15)

## A11 버블 크기 계산
- 테스트 내용: 반지름, 판 넓이 한도에 맞춘 축소, 퍼센트, 0분 제외
- 근거 요구사항: R36, R37, R42
- 수행 방법: features/projects/bubbleScale.ts `bubbleScaleK`·`bubbleRadius`·`bubbleItems`를 실행
- 예상 결과: 반지름 √시간(400분=50), 넓이 합 32% 넘으면 같은 비율 축소, 퍼센트 합 100, 0분 제외
- 실제 결과:
  - 맞음: 400분 → 반지름 50, 100분 → 25. 300×200 판에 400/900/100분을 넣으면 넓이 합이 판의 정확히 32%로 줄고 반지름 비(900:400 = 1.5)는 그대로다. 한도 밑이면 기준 k를 그대로 쓴다. 30초(0분) 프로젝트는 빠지고 시간 많은 순으로 정렬된다. 모두 0분이면 빈 목록
  - 틀림: 퍼센트 합. 100/200/100분이면 50+25+25 = 100이지만, 120/300/45분이면 26+65+10 = **101**이고 60/60/60분이면 33+33+33 = **99**다
- 판정: 실패
- 원인 추정: `bubbleItems`가 퍼센트마다 `Math.round((minutes / total) * 100)`을 따로 해서 반올림 오차가 쌓인다
- 수정 방향: 최대 나머지 방식(내림한 뒤 남은 몫을 나머지가 큰 순서대로 1씩 더함)으로 합을 100에 맞춘다. 합 100을 요구하지 않는다면 승인된 예상 결과를 고친다 (R37 문장에는 "합 100"이 직접 적혀 있지 않음)

## A15 타이머 상태·갱신 주기 (코드 확인)
- 테스트 내용: "진행 중" 표시는 실행 중일 때만 나오는지, 10초마다 확인하고 분 값이 바뀔 때만 다시 그리는지
- 근거 요구사항: R43, R44, D9
- 수행 방법: features/projects/useProjectClock.ts 전체, features/today/useNow.ts, pages/projects/top/BubblePanel.tsx의 `running` 부분을 읽음
- 예상 결과: 실행 중일 때만 진행 중 표시, 10초 확인·분 값 바뀔 때만 다시 그림
- 실제 결과: `runningProjectId`는 `running.state === "running"`일 때만 값이 있고, 일시정지·멈춤이면 null이다. BubblePanel은 이 값이 있을 때만 `● <이름> 진행 중`을 보여준다. `useNow(ticking, 10_000)`은 running일 때만 10초 간격을 건다. 값은 분 단위로 내리고(`floorMinute`), `sameClock`이 같다고 보면 앞의 객체를 그대로 돌려준다(total·week·lastDay·days·runningProjectId 비교)
- 판정: 통과

## 테스트 환경
- Windows 11, Node v24.20.0
- 프론트엔드: `apps/desktop`에서 `npm run build` 후 `npx vite preview --port 4173`으로 띄우고, Claude 앱 안의 브라우저 창으로 확인했다.
  - 실제 Tauri 창(WebView2)이 아니라 같은 빌드 결과를 브라우저로 본 것이다.
  - 창 크기·가운데 띄우기·최소 크기 제한처럼 창 자체의 동작은 사용자 테스트(U1~U3)로 넘겼다.
- 화면 조작: 브라우저 창 크기 조절, 화면 안에서 JavaScript로 버튼 클릭과 계산된 스타일 읽기, 실제 키 입력(Tab, Shift+Tab, Enter, Space)
- 함수 테스트: 테스트 도구가 아직 없어서, 임시 스크립트로 `src/utils/date.ts`, `src/utils/korean.ts`를 Node에서 직접 실행했다. 스크립트는 저장소 밖 임시 폴더에 두었다.
- 범위 밖이라 테스트하지 않음: 실제 데이터 저장/조회, Supabase·로그인, 라이트/다크 전환·설정, 모바일 대응, 자정이 지났을 때 날짜 자동 갱신

### A15. 같은 메뉴 반복 클릭과 빠른 연속 클릭

  2. 마지막 "타이머" 화면, 강조는 "타이머" 1개, 본문 영역 1개
  3. 마지막으로 누른 "스케줄러" 화면과 강조가 같았다.

### A16. 최소 창 크기 960x640

  - 카드 안 요소가 카드 밖으로 나가는지
  - 빈 상태가 본문보다 큰지
  - 제목과 오른쪽 위 링크가 겹치는지
- 예상 결과: 가로 넘침이 없고, 2열이 유지되며, 글자가 겹치거나 잘리지 않는다.

  - 본문 640/640으로 세로 스크롤 없음

### A20. 키보드 조작과 포커스 표시

- 수행 방법: 새로고침 후 실제 키 입력을 순서대로 보냄

  4. Tab 5번
  5. Tab 2번, Enter
- 예상 결과: Tab 순서가 사이드바 → 카드 순이고, Enter·Space로 실행되며, 포커스된 버튼에 강조색 외곽선이 보인다.
- 실제 결과:
  1. "홈"에 포커스되고 외곽선이 보였다.
  2. "캘린더"로 이동한 뒤 Enter로 캘린더 화면이 열렸다.
  3. "홈"으로 돌아간 뒤 Space로 홈 화면이 열렸다.
  4. 첫 카드 제목 "오늘 할 일"에 포커스되고 외곽선이 보였다.
  5. "캘린더로 가기" 버튼에서 Enter를 누르자 캘린더 화면으로 이동했다.

- 판정: 통과
- 참고 2: 카드 버튼으로 다른 화면에 가면, 누른 버튼이 화면에서 사라져서 포커스가 문서 맨 앞(body)으로 돌아간다.
  키보드 사용자는 Tab을 처음부터 다시 눌러야 한다. 기능이 고장 난 것은 아니고 사용성 개선 후보다.
  고친다면 화면이 바뀔 때 본문 제목에 포커스를 옮기는 방법이 있다. 이번 범위 요구사항은 아니라 수정하지 않았다.

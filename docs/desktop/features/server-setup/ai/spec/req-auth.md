# 서버 연결 요구사항: 로그인·계정·데이터 보호 (R28–R36, R51–R53)

### 로그인·계정
- R28. 로그인은 Supabase Auth의 Google 로그인만 쓰고, 로그인할 때는 이메일 확인 권한만 요청한다. (L02에서 변경)
- R29. 자동 세팅에서 처음 로그인한 Google 계정 하나만 이 서버에 로그인할 수 있다. (L02에서 변경)
- ~~R30. 비밀번호는 8자 이상이고, 확인 칸과 같아야 한다.~~ (삭제, L02)
- R31. 로그인 정보(토큰)는 Windows 자격 증명 관리자에 저장해서, 앱을 다시 켜도 로그인이 유지된다.
- R32. 서버는 연결됐는데 로그인이 안 된 상태(로그아웃 후, 토큰 만료, 다른 PC)면 설정 화면 서버 연결 칸에 [Google로 로그인]을 보여준다. (L02에서 변경)
- ~~R33. 비밀번호를 잊었으면 PAT로 본인 확인을 한 뒤 앱에서 새 비밀번호를 정한다.~~ (삭제, L02)
- R51. [Google로 로그인]을 누르면 기본 브라우저에서 Google 로그인 화면을 열고, 끝나면 결과를 앱으로 넘겨받는다. 앱과 Supabase는 Google 비밀번호를 받지 않는다.
- R52. Gmail 읽기 권한은 로그인 때 요청하지 않는다. Gmail을 쓰는 기능이 연결할 때 같은 Google 계정에 추가로 요청한다.
- R53. 허용되지 않은 Google 계정으로 로그인하면 거부하고 "이 서버에 등록된 계정이 아닙니다"라고 알려준다.

### 데이터 보호
- R34. Daybrick의 모든 서버 테이블은 `user_id`를 가지고, RLS로 로그인한 본인의 행만 읽고 쓸 수 있다. 구조 기록 테이블은 읽기만 허용한다.
- R35. 서버 함수는 로그인한 사용자만 부를 수 있고, 그 사용자의 데이터만 다룬다.
- R36. Supabase 주소·키, PAT, Anthropic 키, 로그인 정보는 코드와 저장소에 넣지 않는다. 저장 위치는 [data.md](data.md)를 따른다.

# 서버 연결 요구사항: 자동 세팅 (R11–R19)

### 입력과 사전 확인
- R11. 자동 세팅 화면에서 Supabase PAT, Anthropic API 키, Google OAuth 클라이언트 ID·비밀값을 받는다. (L02에서 변경)
- R12. Anthropic 키는 세팅 전에 요금이 들지 않는 호출로 동작하는지 확인하고, 실패하면 진행하지 않는다.
- R13. PAT는 주소에서 뽑은 프로젝트 id에 접근 권한이 있는지 먼저 확인한다.
- R14. 서버에 Daybrick 구조 번호가 없는데 다른 테이블이 있으면 "빈 프로젝트가 아닙니다"라고 경고하고, 계속할지 묻는다.

### 실행
- R15. [세팅 시작]을 누르면 아래 단계를 차례로 실행하고, 단계마다 대기·진행·완료·실패를 보여준다. (L03에서 변경)

| 순서 | 단계 | 하는 일 |
|---|---|---|
| 1 | 인증 설정 | Google 로그인 켜기(클라이언트 ID·비밀값 등록), 이메일 로그인 끄기 |
| 2 | 서버 구조 적용 | 테이블·RLS를 0번에서 최신 번호까지 적용 (R22) |
| 3 | 서버 함수 배포 | 앱이 가진 서버 함수 배포 |
| 4 | 비밀값 등록 | Anthropic 키와 Google 클라이언트 ID·비밀값을 서버 함수 비밀값으로 등록 (Gmail 확인 함수가 씀), 등록일 기록 |
| 5 | 계정 등록 | 브라우저에서 Google 로그인(R51), 로그인한 계정을 주인으로 등록하고 그 계정만 허용 (R29) |
| 6 | 마무리 확인 | 서버 함수를 불러 접속·비밀값 동작 확인 |

- R16. 각 단계는 다시 실행해도 안전하다. 이미 있는 것은 건너뛰고 데이터를 지우지 않는다.
- R17. 단계가 실패하면 거기서 멈추고 이유와 [다시 시도]를 보여준다. 다시 시도하면 실패한 단계부터 이어간다.
- R18. PAT, Anthropic 키, Google 클라이언트 비밀값은 메모리에만 두고, 세팅 흐름이 끝나거나 취소되면 버린다. 파일·로그·오류 메시지에 남기지 않는다. (L02에서 변경)
- R19. 세팅이 끝나면 5단계에서 로그인한 상태로 ④ 완료 화면을 보여준다. (L02에서 변경)

## 화면 구성
```
입력 상태:                              실행 상태:
 Supabase PAT          [••••••••] ?      ✓ 인증 설정
 Anthropic API 키      [••••••••] ?      ✓ 서버 구조 적용 (0 → 1)
 Google 클라이언트 ID  [        ] ?      ● 서버 함수 배포 중…
 Google 클라이언트 비밀값 [••••] ?       ○ 비밀값 등록
 리디렉션 주소 https://…/callback [복사] ○ 계정 등록 (Google 로그인)
                       [세팅 시작]       ○ 마무리 확인
                                         (실패 시: 이유 + [다시 시도])
```

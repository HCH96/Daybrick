# 서버 연결: 범위

## 이번 범위에서 제외하는 것
- 여러 계정, 이메일·비밀번호 로그인, 매직 링크, Google 외 소셜 로그인
- Gmail 연결 자체 (job-search에서, 같은 Google 계정에 권한 추가)
- 지원 관리 등 로컬 데이터의 서버 동기화
- 계정 삭제, 서버 초기화(데이터 삭제)
- 앱 자체의 자동 업데이트 배포
- 공유 웹·안드로이드 앱의 서버 연결 (각 기능에서)
- AI 호출 공용 처리와 한도 검사 (job-search에서)

## 나중에 고려할 것
- 서버 데이터 백업·내보내기
- 계정 삭제·서버 초기화
- 공유 웹이 쓸 읽기 전용 공개 범위

## 계획 단계에서 확인할 것 (지금은 추측)
- Supabase 관리 API로 SQL 실행, 서버 함수 배포, 비밀값 등록, 인증 설정 변경, 프로젝트 재개가 모두 되는지와 PAT 권한 범위
- 관리 API를 웹뷰에서 부르면 CORS에 막히는지 (막히면 Rust 쪽에서 호출)
- 관리 API로 Google 로그인 설정(클라이언트 등록, 이메일 로그인 끄기)이 되는지
- Google 계정 하나만 허용하는 방법 (첫 로그인 뒤 가입 막기, 가입 전 검사 훅 등)
- 데스크톱 앱에서 Google 로그인 결과를 넘겨받는 방법 (딥링크 또는 PC 내부 주소, PKCE)
- Google 클라이언트 하나로 로그인과 이후 Gmail 권한 추가를 모두 처리할 수 있는지
- 일시정지된 프로젝트가 돌려주는 응답 모양 (상태 구분 방법)
- 무료 플랜에서 어떤 요청이 "사용"으로 인정돼 일시정지를 막는지
- supabase-js가 publishable 키를 그대로 받는지
- Windows 자격 증명 관리자의 값 크기 제한 (토큰이 크면 나눠 저장하거나 refresh 토큰만 저장)
- Anthropic 키를 요금 없이 확인하는 호출 (모델 목록 조회 등)

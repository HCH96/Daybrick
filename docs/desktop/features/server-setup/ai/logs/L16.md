# L16 · 2026-10-26 · 수정: ② 주소 형식 검사가 정상 주소를 막음 (r1 U8)

- 요구사항: R4
- 한 일: r1 사용자 테스트 10번(U8)에서 P1 주소를 넣으면 "주소 형식이 맞지 않습니다"가 떠서 진행이 막혔다. 기존 검사는 `https://<ref>.supabase.co` 뒤에 `/` 하나만 허용했다. 원인: Supabase 대시보드의 복사 버튼은 주소를 `https://<ref>.supabase.co/rest/v1/`로 복사한다(사용자 확인). 기존 검사는 이 REST 경로를 막았다. 검사가 REST 경로 `/rest/v1`, 끝의 `/` 여러 개, 공백·줄바꿈, 보이지 않는 글자(폭 없는 공백·BOM)를 받도록 고쳤다. [확인]을 누를 때 형식이 맞으면 입력칸 값도 정리한 주소(끝 `/`와 경로를 뗀 것)로 바꾼다.
- 계획과 달라진 점: R4 주소 형식을 넓혔다(사용자 요청: 끝 `/` 자동 제거).
- 확인: `npm run build` 성공. `parseSupabaseUrl`을 실행해 `/`, `/rest/v1/`, 대문자, 앞뒤 공백·폭 없는 공백을 정상으로 받고, `http://`, `.supabase.com`, `/auth/v1`, `https://` 없는 주소는 막는 것을 확인했다. 브라우저 미리보기 ②에서 `…/rest/v1/`를 입력하고 [확인]을 누르면 입력칸이 `https://…supabase.co`로 바뀌고 형식 검사를 넘어 접속 단계로 가는 것을 봤다(가짜 주소라 "접속할 수 없습니다"가 뜸).
- 사용자 확인: 대기 (r1 U8 다시 확인)
- 추가 수정: 마법사 가이드 그림의 Project URL 예시를 실제 복사 값 모양인 `https://xxxx.supabase.co/rest/v1/`로 바꿨다(사용자 요청). 입력칸 예시 글자(placeholder)는 그대로 뒀다. 다시 `npm run build` 성공.

# 서버 연결 (server-setup) 사용자 테스트 r1
- 근거: [명세서](../../ai/spec/index.md) · [구현 계획](../../ai/plan/index.md) · [목업](../mockups/index.html)
- AI 테스트 보고서: [../../ai/tests/r1/](../../ai/tests/r1/)
- 실행: `apps/desktop`에서 `npm run tauri dev` (U33·U34만 임시 빌드, 해당 항목 참고)
- 색 이름: 초록 `#66CF95`, 주황 `#F0B860`, 빨강 `#FF8A8A`, 보라 = 앱 강조색, 회색 = 연결 안 함

## 준비
1. **계정·값 준비**
   - Supabase 테스트 프로젝트 **P1**: 새로 만든 빈 프로젝트. 주소(Project URL), anon 키(`eyJ…`), publishable 키(`sb_publishable_…`), secret 키(`sb_secret_…`)를 메모장에 복사해 둔다.
   - Supabase 테스트 프로젝트 **P2**: 다른 빈 프로젝트를 하나 더 만들고, 대시보드 SQL Editor에서 `create table test_x (id int);`를 실행해 테이블을 하나 둔다 (U17용, U42에서 연결 대상으로도 씀).
   - **PAT-1**: Supabase 계정 설정 → Access Tokens에서 발급. 틀린 PAT로 쓸 `sbp_0000` 같은 아무 값도 적어 둔다.
   - **PAT-다른 계정**(있으면): P1을 관리하지 않는 다른 Supabase 계정의 PAT (U16). 없으면 그 칸은 "확인 못 함".
   - **Anthropic 키 K1**과 교체용 **K2** (콘솔에서 두 개 발급). 틀린 키로 쓸 `sk-ant-0000`.
   - **Google 계정 G1**(주인으로 쓸 계정)과 **G2**(다른 계정, U26용).
   - Google Cloud OAuth 클라이언트(웹 애플리케이션). 리디렉션 주소는 U13에서 복사해 넣는다.
2. **파일 위치** (Windows)
   - 앱 설정 파일: `%APPDATA%\com.daybrick.desktop\server.json` (탐색기 주소창에 그대로 붙여넣기)
   - 로그인 정보: 제어판 → 자격 증명 관리자 → Windows 자격 증명 → `Daybrick/<프로젝트id>` 항목
3. **처음 상태 만들기**: 앱을 끄고 `server.json`이 있으면 바탕화면에 옮겨 둔다 (테스트가 끝나면 되돌리기). 자격 증명 관리자에 `Daybrick/…` 항목이 있으면 지운다.
4. **네트워크 끊기 방법**: Windows 설정 → 네트워크 → 비행기 모드 켜기/끄기 (또는 Wi-Fi 끄기).
5. 지원 관리에 카드를 하나 만들어 둔다 (**카드 A**, 이름 "테스트 카드"). 로컬 데이터가 그대로인지 볼 때 쓴다.

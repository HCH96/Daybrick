## 결정 (계획 중 정함, D1–D5)
- updater 플러그인은 Rust에서만 쓰고, 프론트는 우리 명령만 부른다 (D1).
- 받기와 설치를 나눈다. 받은 파일은 메모리에만 두고 [나중에 설치]·서명 실패·종료 때 버린다 (D2).
- 알림: 보낸 기능 `updater`, 합치기 키 `update-available`·`update-failed`, 갈 곳 `{page:"settings", tab:"app"}` (D3).
- 첫 확인은 화면이 뜨고 5초 뒤, 그 뒤는 1시간마다 "마지막 확인 뒤 24시간이 지났나"만 본다 (D4).
- `app-settings.json`이 깨져 있으면 "알린 버전"을 쓰지 않고 건너뛴다 (D5, R36).

### 작은 규칙
- 이 기능이 들어간 첫 버전은 0.2.0, 완료 확인용 테스트 릴리즈 B는 0.2.1.
- 이번 설치 흐름에서 이미 [기록 저장하고 설치]를 골랐으면 설치 직전에 다시 묻지 않는다.
- 확인 중·받는 중에는 자동 확인을 건너뛴다. 수동 확인과 자동 확인은 겹치지 않는다.
- 확인 창 문구: 제목 "업데이트 설치", 본문 "타이머가 실행 중이에요. 기록을 저장하고 설치할까요?", 버튼 [나중에 설치]/[기록 저장하고 설치].
- 오류 종류: 서명(`Minisign`·`Base64`·`SignatureUtf8` 등) → "signature", 그 밖 → "network".
- 설치 뒤 설치 프로그램이 앱을 다시 띄우는지는 추측이다. 6단계에서 실제로 확인하고, 안 되면 방법을 다시 정한다.
- 개발 모드 화면 확인용 `window.daybrickUpdater`(개발 모드 전용)로 상태를 흉내 낸다.

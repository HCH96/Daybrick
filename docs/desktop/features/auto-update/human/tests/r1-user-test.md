# 자동 업데이트 사용자 테스트 체크리스트 (r1)

- 근거: 명세 R1–R36, 계획 step-01~06 "확인할 결과", 진행 기록 테스트 메모 (L02–L09)
- AI 테스트 보고서: [../../ai/tests/r1/](../../ai/tests/r1/)
- **(L09 확인)** 표시 항목은 2026-11-10 실제 업데이트(0.2.0 → 0.2.1)에서 사용자가 이미 "잘 된다"고 확인한 것이다. 다시 보지 않아도 된다.
- 결과 칸은 사용자가 채운다.

## 준비
- **설치본**: 지금 설치된 0.2.1 (`%LOCALAPPDATA%\Daybrick`). 트레이 아이콘 → 종료로 끈다. 창 X는 숨기기만 한다.
- **개발 모드**: 설치본을 트레이에서 종료한 뒤 `apps/desktop`에서 `npm.cmd run tauri dev`. 같은 데이터 폴더를 쓴다.
- **흉내 명령**: 개발 모드 창에서 `Ctrl+Shift+I` → Console 탭에 입력한다.
  - 새 버전 상태: `daybrickUpdater("available")`
  - 받기 시작 흉내: [설치하고 다시 시작]을 누르거나 `daybrickUpdater("install")`. 받는 중 42%에서 멈춰 기다린다.
  - 받기 끝: `daybrickUpdater("done")` / 실패: `("fail")` / 서명 실패: `("badSignature")`
  - 개발 모드에서는 `done` 뒤 종료 전 저장만 돌고 "설치 중"으로 남는다. 되돌리려면 `daybrickUpdater("available")`.
- **타이머 A**: 투데이에서 아무 태스크로 타이머를 하나 켠다.

### 9. 개발 모드 흉내로 상태별 화면 보기
- 근거 요구사항: R13, R20, R22, R23
- 수행 방법: 개발 모드 콘솔에서 차례로 입력하고 매번 업데이트 줄을 본다
  1. `daybrickUpdater("available", { notes: null })`
  2. `daybrickUpdater("downloading", { percent: 42 })`
  3. `daybrickUpdater("downloading", { percent: null })`
  4. `daybrickUpdater("downloadFailed")`
  5. `daybrickUpdater("signatureFailed")`
- 예상 결과:
  1. "새 버전 …"과 설치 버튼만 있고 변경 내용 줄은 없다
  2. "받는 중 42%"와 얇은 진행 막대가 42%쯤 차 있다. 두 버튼 비활성
  3. 막대 없이 "받는 중…"
  4. "업데이트를 받지 못했어요. 다시 시도해 주세요."
  5. "업데이트 파일을 확인하지 못해 설치하지 않았어요."
  - 개발 모드라 두 버튼은 계속 비활성인 게 정상이다
- 확인 위치: 업데이트 줄
- 실제 결과:

### 10. 타이머 확인 창과 [나중에 설치]

- 확인 위치: 화면 가운데 확인 창, 업데이트 줄

### 13. 실패 알림은 하나로 합침

- 수행 방법: `("available")` → `("install")` → `("fail")`. 다시 `("install")` → `("badSignature")`. 알림은 읽지 않는다

- 확인 위치: 종 아이콘 목록, 업데이트 줄

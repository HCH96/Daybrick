# L12 · 2026-11-03 · 구현 8단계: 미완료 팝업

- 요구사항: R7, R34–R39
- 한 일: `overdue.ts`에 `listOverdue`(끝일 오래된 순 → 시작일 → 만든 때)·`bringToToday`·`postponeTo`·`periodLength`를 두고, `format.ts`에 `formatDateRange`·`formatOverdueDays`를 더했다. `pages/today/overdue/`에 팝업(720px, 빨간 개수)·줄(색 점·제목·N일 지남, 카테고리·원래 기간·상태, 버튼 3개와 마우스 올림/포커스 미리보기)·미루기 달력을 만들었다. 가져오기·미루기는 `updateTask(id, { start, end })`, 완료는 `updateTask(id, { status: "done" })`. 목록이 0이 되면 팝업을 닫는다. `WeekProgress`의 `미완료 N` 버튼이 팝업을 연다(개수도 `listOverdue`로 센다).
- 계획과 달라진 점: 팝업 열기 상태는 `TodayPage`가 아니라 `WeekProgress` 안에 두어 `TodayPage`는 고치지 않았다. 미루기 달력은 `Popover`(버튼 아래)로 띄워 팝업 밖으로 걸쳐도 잘리지 않게 했다. `MiniCalendar`에 `weekStartsOn`·`isDisabled`·`highlighted` 옵션을, `getMonthGrid`에 `weekStartsOn`(기본 일요일, 기존 호출은 그대로)을 더했다. 칠하는 기간은 바뀔 기간 중 오늘 뒤의 날만이다. 원래 기간 뒤 "(N일)"은 시작 전 태스크만 붙인다(목업대로). 2단계에서 빠져 있던 진행 바 CSS(`WeekProgress.css`, 목업 week-label·bar·week-count·overdue-btn 값)를 새로 만들었다. 아이콘 `BringInIcon`을 `TodayIcons.tsx`에 더했다 (자동 진행 중 판단)
- 확인: `npm run build` 성공 (타입 검사 포함). Rust는 고치지 않았다. Node로 overdue.ts·format.ts를 컴파일해 실행: 진행 중 가져오기 10/28~11/03·미루기 10/28~11/10, 시작 전 가져오기 11/03~11/05·미루기 11/10~11/12, 목록은 완료·날짜 없음·끝일 오늘을 빼고 끝일 오래된 순, "4일 지남". 화면은 띄워 보지 않았다
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 이번 주 진행 바 모양(막대·버튼)이 이번 단계에서 처음 꾸며졌으니 같이 본다. 미루기 달력이 열린 채 Esc는 달력만 닫는다. 실행 중 태스크를 팝업에서 완료하면 타이머도 완료(D10)

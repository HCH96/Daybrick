# 알림: 결정 사항
모든 앱이 따르는 서버 규칙은 supabase/CLAUDE.md로 모았다 (원본). 거기 옮긴 결정을 바꾸면 그 파일을 먼저 고친다.

- D1. 푸시 알림·OS 알림은 쓰지 않고 앱 안 알림 센터만 쓴다. (적용: 이후 전체) (기록: L01)
- D2. 확인은 체크 버튼을 누르거나 알림을 눌러 이동할 때만 하고, 패널을 펼치기만 해서는 확인하지 않는다. 확인한 알림은 "전체" 필터에서 흐리게 남긴다 ("안 읽음" 필터는 D18). (적용: 이후 전체) (기록: L01) (L16에서 변경)
- D3. 앱이 만든 알림은 로컬에, 서버 작업이 만든 알림은 서버 테이블에 두고 목록에서 합쳐 보여준다. 서버 알림의 확인 여부는 서버에 기록한다. (적용: 이후 전체) (기록: L01)
- D4. 서버 알림은 앱을 켤 때 받아 오고, 켜져 있는 동안은 실시간으로 받는다. (적용: 이후 전체) (기록: L01)
- D5. 확인한 알림은 30일 뒤 지우고, 목록은 최근 50개까지 보여준다. 안 읽은 알림은 지우지 않는다. (적용: 이후 전체) (기록: L01)
- D6. 같은 합치기 키의 안 읽은 알림이 있으면 새로 만들지 않고 갱신한다. (적용: 이후 전체) (기록: L01)
- D7. 서버 연결 상태 문제는 알림이 아니라 server-setup 안내 띠로만 보여준다. (적용: 이후 전체) (기록: L01)
- D8. 로컬 알림은 Rust 명령으로 앱 데이터 폴더 `notifications.json`(`{version, local, serverCopy, pendingAcks}`)에 저장하고, 임시 파일 바꿔치기로 쓴다. 지원 관리와 같은 방식이다. (적용: 이후 전체) (기록: L03)
- D9. 다른 기능은 `features/notifications/notify.ts`의 `notify(input)` 하나로 알림을 보낸다. Provider 등록 전에 온 알림은 대기 줄에 두었다가 처리하고, 합치기는 순수 함수 `mergeNotification`이 한다. (적용: 이후 전체) (기록: L03)
- D10. 갈 곳 이동은 `navigate`를 고치지 않고 열기 요청 Context(`app/pageIntent.tsx`의 `openTarget`/`usePageIntent`)로 한다. 이동할 수 없으면 확인 처리만 한다. (적용: 5단계 이후 전체) (기록: L03)
- D11. 서버 알림 정리는 pg_cron 없이 앱이 받아 올 때 확인한 지 30일 지난 행을 지운다. 서버 합치기는 SQL 함수 `daybrick_notify`와 부분 고유 인덱스로 한다. (적용: 6단계 이후 전체) (기록: L03)
- D12. 실시간은 `user_id`로 걸러 구독하고, `SUBSCRIBED`가 될 때마다 전체를 다시 받아 끊긴 동안 빠진 알림을 메운다. (적용: 7단계 이후 전체) (기록: L03)
- D13. `openTarget`은 `useOpenTarget()` 훅으로 얻는다. `PageIntentProvider`는 평소 화면(AppLayout)만 감싸고, 전체 화면(FullScreen)에는 두지 않아 그곳에서는 `openTarget`이 늘 false다. 이미 확인한 알림의 본문을 눌러도 확인 시각은 바꾸지 않는다. (적용: 5단계 이후 전체) (기록: L08)
- D14. `daybrick_notify`는 만든(또는 갱신한) 행의 id(uuid)를 돌려준다. 실행 권한은 `authenticated`·`service_role`만 가진다. 대상 사용자는 로그인 사용자면 본인, JWT 역할이 `service_role`이거나 JWT가 없을 때(SQL 편집기 직접 실행)만 `p_user_id`를 쓰고, 그 밖에는 오류를 낸다. 합칠 때는 제목·내용·`updated_at`만 바꾼다. (적용: 6단계 이후 전체) (기록: L09)
- D15. 서버 알림은 연결될 때 한 번 바로 받고, 구독이 `SUBSCRIBED`가 될 때마다 다시 받는다(실시간 구독이 실패해도 목록은 받도록). 겹쳐 받으면 마지막 요청 결과만 쓴다. 받은 목록은 `serverCopy`를 통째로 바꾸고, 실시간 행은 같은 id를 바꾸거나 앞에 넣는다. 앱을 켤 때 `serverCopy`도 로컬과 같은 30일 기준으로 지운다. 목록·배지는 `local`과 `serverCopy`를 합쳐 계산한다. (적용: 7단계 이후 전체) (기록: L10)
- D16. 서버 알림의 확인·되돌림·[모두 확인]은 reducer가 `serverCopy`를 바꾸면서 곧바로 `pendingAcks`에 쌓고(같은 id는 마지막 기록만), 서버 쓰기에 성공한 기록만 `id`와 `at`이 같을 때 지운다. 연결된 동안은 대기 기록이 바뀔 때마다, 연결되면 받기 전에 먼저 서버에 쓴다. 같은 `readAt` 값끼리는 한 번에 쓰고, 실패하면 그 자리에서 멈춘다. 받아 온 목록·실시간 행에는 대기 기록을 덮어씌운다. (적용: 8단계 이후 전체) (기록: L11)
- D17. 로컬 알림 시각은 겹치지 않게 저장한다. `mergeNotification`이 새로 만들거나 합칠 때 시각이 목록의 가장 늦은 `updatedAt` 이하이면 그보다 1ms 뒤로 저장한다. 목록 정렬은 `updatedAt` 최신순 → `createdAt` 최신순 → id 내림차순이고, 50개 자르기는 그 결과에서 한다. (적용: 수정1 1단계 이후 전체) (기록: L16)
- D18. "안 읽음" 필터에서 확인한 알림은 패널 안에 따로 기억하지 않고 바로 뺀다. 되돌리기는 "전체" 필터의 ↺로 한다. (적용: 수정1 2단계 이후 전체) (기록: L16)

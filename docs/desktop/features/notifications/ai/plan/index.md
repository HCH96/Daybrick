## 결정 (계획 중 정함, D17–D18)
- 로컬 알림 시각은 겹치지 않게 저장한다. 새로 만들거나 합칠 때 시각이 목록의 가장 늦은 `updatedAt` 이하이면 그보다 1ms 뒤로 저장한다. 정렬은 `updatedAt` 최신순 → `createdAt` 최신순 → id 순 (D17).
- 안 읽음 필터에서는 확인한 알림을 바로 뺀다. 전체 필터는 흐리게 남긴다 (D18, D2 변경).

### 작은 규칙
- 저장 파일 모양은 바뀌지 않는다. 데이터 옮기기 단계는 없다.
- 화면에 보이는 시각은 1ms 차이로 달라지지 않는다.
- 50개 자르기는 정렬 결과에서 하므로 `sortForList` 하나만 고치면 함께 맞는다.

## 이번 계획에 넣지 않는 것
- 서버 알림끼리 같은 시각 문제: SQL 편집기에서 한 번에 여러 번 실행하면 `now()`가 같아진다. 보조 기준(createdAt → id)으로만 순서를 정하고, 서버 함수 수정(서버 구조 3)은 하지 않는다.
- 이미 저장된 같은 시각의 테스트 알림은 다시 쓰지 않는다. 테스트 전에 `notifications.json`을 지우고 시작한다.
- 목업 수정 (panel-states.html `states-unread`는 흐린 행이 남은 모습 그대로 둔다).
- r1 빠른 체크리스트 12번(오프라인, 보류).

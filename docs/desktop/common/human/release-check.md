# PC 앱 출시 확인 목록
사람이나 실제 환경만 확인할 수 있는 항목을 모아 둔다. 기능마다 체크리스트를 따로 만들지 않고, `/test`가 여기에 한 줄씩 올린다.
출시(설치 파일을 만들어 버전을 올릴 때) 전에 "대기"에서 이번 버전에 들어간 기능의 항목을 10개 안팎 골라 새 설치본으로 확인한다. 절차는 docs/desktop/common/ai/setup/desktop-release.md.

## 규칙
- ID는 C1부터 차례로 붙이고 바꾸지 않는다.
- 이유: 실제 서버 / 실제 계정 / 외부 사이트 / OS 기능 / 실사용 중 하나.
- 추가: `<기능명> <회차> <테스트 ID>` (예: today r2 C3).
- 확인하면 그 줄을 "확인함" 표로 옮기고 확인한 버전을 적는다. 문제가 있으면 "확인함"으로 옮기지 않고 결과 칸에 적은 뒤 수정 작업을 시작한다.
- 표가 40줄을 넘으면 "확인함" 표를 같은 폴더의 release-check-done.md로 옮긴다.

## 대기
| ID | 기능 | 확인할 것 | 예상 결과 | 이유 | 추가 | 결과 |
|---|---|---|---|---|---|---|
| C1 | job-search | 서버 업데이트 뒤 Job Search에서 [지금 평가]를 누른다 (이미지가 큰 대기 공고 5개가 있는 상태) | "일괄 처리로 맡겼어요: 추출 N개 …"가 뜨고, 함수 로그에 Memory limit exceeded가 다시 나오지 않는다 | 실제 서버 | job-search fix L64 | |
| C2 | job-search | 시프트업만 켜고 [지금 수집] 뒤 [지금 평가]를 누른다 (10/29 시프트업 공고 40개를 L67에서 처음 단계로 되돌린 상태) | 되돌린 공고에 원문이 채워지고, 처리 뒤 상세 팝업의 추출 항목(자격 요건·기술스택 등)이 채워진다 | 실제 서버 / 외부 사이트 | job-search fix L67 | |

# PC 앱 테스트 방식
2026-11-11부터. 기능마다 사람이 2~3시간짜리 체크리스트를 돌리던 방식을 바꿨다 (기록: docs/common/ai/logs L04).
사람이 하던 화면 확인은 AI가 브라우저 미리보기로 대신하고, 사람은 출시 때 실제 환경만 짧게 확인한다.

## 세 주체
| 주체 | 누가 | 어디서 | 보고서 |
|---|---|---|---|
| AI 코드 | 하위 에이전트 test-ai | 빌드·코드·순수 함수 실행 | ai/tests/<회차>/index.md 외 |
| AI 화면 | 하위 에이전트 test-ui | 브라우저 미리보기 + 예시 데이터 | ai/tests/<회차>/ui.md |
| 출시 확인 | 사람 | 새 설치본, 실제 계정·서버 | docs/desktop/common/human/release-check.md |

- AI 코드 테스트는 먼저 `npm test`(Vitest 단위 테스트, apps/desktop)를 돌린다. 이미 테스트가 있는 순수 함수는 그 결과로 판정하고, 없는 것만 임시 스크립트로 실행해 본다. 지금 테스트가 있는 곳: utils/date, today(reducer·stats), notifications/logic, sync(stableJson·latestUpdatedAt).
- AI 코드와 AI 화면을 통과하면 기능은 완료다. 출시 확인 항목은 출시 때 모아서 본다.
- 평소에는 앱을 실제로 쓰다가 문제가 생기면 고친다.
- 이 방식 전에 만든 사용자 체크리스트(각 기능 human/tests/)는 진행하지 않고, 출시 확인 목록으로 옮기지도 않는다 (2026-11-11 사용자 결정: 실사용으로 잘 동작함). 다시 하자고 권하지 않는다.

## 브라우저 미리보기
- 실행: 미리보기 설정 `desktop-web` (`npm run dev`, http://localhost:1420). Tauri 밖이라 서버·트레이·창 조작·파일 위치는 동작하지 않는다.
- 데이터: 개발 모드에서는 앱 데이터를 localStorage에 둔다 (`apps/desktop/src/dev/previewStore.ts`). 출시 빌드와 Tauri 앱에는 영향이 없다.
- 예시 데이터: 주소에 `?fixture=basic`(기능마다 몇 개씩 채운 보통 상태, 날짜는 오늘 기준) 또는 `?fixture=empty`(빈 상태). 저장된 미리보기 데이터를 지우고 새로 넣는다. 내용은 `apps/desktop/src/dev/fixtures/basic.ts` 맨 위 설명.
- 예시 데이터가 부족하면 `dev/fixtures/`에 새 묶음을 만들고 `fixtures/index.ts`의 목록에 올린다. 서버 기능용 예시는 아직 없다.

## 토큰 아끼기 (test-ui 규칙 요약)
- 글자·구조 읽기로 판정하고, 스크린샷은 모양을 봐야 할 때만 절반 크기로 찍는다.
- 한 에이전트에 항목 15개까지. 넘으면 나눠 띄운다.
- 메인 세션은 미리보기를 직접 열지 않고 요약만 받는다.
- 실측 (2026-11-11 시험 실행, 투데이 5항목): 하위 에이전트 호출 20회, 캐시 읽기 약 122만, 최대 컨텍스트 약 7만 4천. 항목 15개면 대략 370만~450만으로 본다.

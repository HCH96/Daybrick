# 지원 관리 (applications)

## 기능 개요
지원한 채용 공고를 카드로 정리하고, 상태와 전형 일정을 갤러리와 달력으로 관리한다. 카드 본문은 마크다운으로 자유롭게 기록한다.

## 요구사항

### 지원 관리 페이지
- R1. 페이지 위쪽에 `갤러리 | 달력` 전환 버튼을 둔다. 기본은 갤러리다.
- R2. 오른쪽 위 "+ 새 지원" 버튼으로 카드를 만든다. 새 카드의 상태는 "지원 준비"이고 다른 속성은 모두 "없음"이다.

### 갤러리
- R3. 카드를 바둑판처럼 나열한다.
- R4. 위쪽에 `진행 중 | 종료 | 전체` 탭을 둔다. 기본은 "진행 중"(종료가 아닌 카드)이다.
- R5. 기본 정렬은 마감일이 가까운 순이다. 마감일이 없는 카드는 맨 뒤에 둔다.
- R6. 카드 앞면에는 제목, 상태 배지(세부 단계 포함), 회사, 다음 일정(예: "D-3 코딩테스트"), 우선순위를 보여준다.

### 달력
- R7. 월 단위 달력에 각 카드의 전형 일정을 표시한다. 형식은 `<카드 제목> · <일정 종류>`다.
- R8. 지원 준비 상태인 카드의 마감일은 전형 일정과 구분되게 흐린 색으로 표시한다.
- R9. 대기·준비 같은 상태 자체는 달력에 표시하지 않는다.
- R10. 종료된 지원의 지난 일정도 달력에 남긴다.
- R11. 달력의 일정을 누르면 그 카드의 상세 팝업이 열린다.

### 상세 팝업
- R12. 카드를 누르면 앱 안 가운데에 팝업이 뜬다. OS 창이 아니다.
- R13. 왼쪽 위 최대화 버튼을 누르면 본문 영역을 꽉 채운다. 사이드바가 펼쳐져 있으면 사이드바는 남기고, 접혀 있으면 사이드바 자리까지 채운다. 내용은 가운데 정렬로 보여준다.
- R14. 팝업은 위에서부터 제목 → 상태 배지와 일정 버튼 → 속성 목록 → 본문 순서로 구성한다.
- R15. 고치는 즉시 자동 저장한다. 저장 버튼은 없다.
- R16. 카드를 삭제할 수 있고, 삭제 전에 확인 창을 띄운다.

### 상태 (최상위 속성)
- R17. 상태는 일반 속성과 구분해 제목 아래 큰 배지로 보여준다.
- R18. 배지를 누르면 "상태 → 세부 단계" 두 단계로 고른다.
- R19. 상태 목록은 고정이며 사용자가 편집할 수 없다. 상태마다 색이 정해져 있다.
- R20. 종료는 어느 상태에서든 바로 고를 수 있다. 종료로 바꾸면 결과를 고르는 칸이 바로 뜬다.
- R21. 지원 완료로 바꾸면 오늘 날짜로 "지원 완료" 일정이 생기고, 지원일 속성이 비어 있으면 함께 채운다 (이미 채워져 있으면 덮어쓰지 않는다).
- R22. 전형 준비의 세부 단계로 바꾸면 그 전형의 날짜를 고를 작은 달력이 뜬다. 건너뛸 수 있다.

상태와 실제 지원 과정의 대응:

| 상태 | 세부 단계 | 해당 과정 | 홈에서 세기 |
|---|---|---|---|
| 지원 준비 | 없음 | 자소서·포트폴리오 작성 | 셈 |
| 지원 완료 | 없음 | 제출 후 서류 결과 대기 | 셈 |
| 전형 준비 | 과제 / 코딩테스트 / 면접 | 서류 통과, 다음 전형 안내 받고 준비 | 셈 (세부별로도) |
| 결과 대기 | 과제 / 코딩테스트 / 면접 | 전형을 마치고 결과 대기, 면접 후 발표 대기 | 셈 (세부별로도) |
| 종료 | 없음 | 모든 전형이 끝남 | 세지 않음, 홈에 안 보임 |

### 전형 일정
- R23. 전형 일정은 속성 목록에 나오지 않는다. 카드 내부 정보로만 저장한다.
- R24. 상태 배지 옆 📅 버튼 옆에 다음 일정 하나만 보여준다 (예: "D-3 코딩테스트"). 앞으로 남은 일정이 없으면 아무것도 보이지 않는다.
- R25. 📅 버튼을 누르면 작은 창이 열린다. `지원 완료` `과제 마감` `코딩테스트` `면접` 버튼 중 하나를 누르고 작은 달력에서 날짜를 클릭하면 저장된다.
- R26. 같은 창에서 저장된 일정 목록을 보고, 날짜·시간·메모를 고치거나 지울 수 있다.
- R27. 같은 종류의 일정을 여러 개 저장할 수 있다 (예: 1차·2차 면접은 메모로 구분).

### 속성
- R28. 속성을 추가·삭제·편집(이름, 종류, 항목)할 수 있다.
- R29. 속성 종류는 텍스트, 숫자, 선택, 다중 선택, 날짜, URL, 체크박스 7가지다.
- R30. 선택·다중 선택의 항목은 쓰면서 추가할 수 있고, 항목마다 색을 직접 고를 수 있다.
- R31. 모든 속성의 기본값은 "없음"이며 빈칸으로 보여준다.
- R32. 날짜 속성은 직접 타이핑하지 않고 작은 달력에서 클릭해 고른다.
- R33. 제목과 상태는 삭제할 수 없다. 나머지 기본 속성은 삭제할 수 있다. 지원일을 삭제하면 R21의 자동 입력도 하지 않는다.

### 본문 (마크다운)
- R34. 쓰는 즉시 서식이 반영되는 Notion식 편집기를 사용한다. 원문과 결과 화면이 나뉘지 않는다.
- R35. 이미지를 붙여 넣을 수 있다. 이미지 파일은 PC의 앱 데이터 폴더에 저장한다. 이미지 크기 조절은 이번 범위에 넣지 않는다.

### 홈 연동
- R36. 홈의 지원 현황 카드를 이번 상태 구조로 바꾼다. 상태별 개수와 함께, 전형 준비·결과 대기는 세부 단계별 개수도 보여준다 (예: "전형 준비 3 · 과제 1 · 코테 1 · 면접 1").
- R37. 종료된 지원은 세지 않고 홈에 보여주지 않는다.

## 화면 구성

**지원 관리 페이지 (갤러리)** (R1–R6)
```
지원 관리                         [갤러리 | 달력]   [+ 새 지원]
[진행 중] [종료] [전체]
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 제목          │ │ 제목          │ │ 제목          │
│ [전형 준비·코테]│ │ [지원 완료]    │ │ [지원 준비]    │
│ 네오플        │ │ 넥슨          │ │ (회사 빈칸)    │
│ D-3 코딩테스트 │ │               │ │ D-5 마감      │
│ 높음          │ │ 중간          │ │               │
└──────────────┘ └──────────────┘ └──────────────┘
```

**지원 관리 페이지 (달력)** (R7–R11): 월 이동 버튼과 월 달력이 있고, 날짜 칸마다 `제목 · 일정 종류`가 줄지어 표시된다. 지원 준비 카드의 마감일은 흐린 색으로 표시한다.

**상세 팝업** (R12–R33)
```
┌ [⤢]                                         [🗑] [✕] ┐
│   [던전앤파이터] 클라이언트/엔진 프로그래머            │
│   [전형 준비 · 코딩테스트 ▾]   📅 D-3 코딩테스트      │
│   결과      (빈칸)                                  │
│   회사      [네오플]                                │
│   ...                                              │
│   + 속성 추가                                       │
│   ─────────────────────────────                    │
│   (마크다운 본문, 이미지 포함)                        │
└────────────────────────────────────────────────────┘
```
최대화하면 본문 영역 전체를 채운다(R13). 삭제·닫기 버튼 위치는 목업 단계에서 정한다. (→ 정함, 위 "목업에서 정한 것" 참고)

## 다룰 데이터

**지원 (카드 하나)**
| 항목 | 설명 |
|---|---|
| id | 고유 번호 |
| 제목 | 텍스트, 비어 있을 수 있음 |
| 상태 | 지원 준비 / 지원 완료 / 전형 준비 / 결과 대기 / 종료 |
| 세부 단계 | 전형 준비·결과 대기일 때만: 과제 / 코딩테스트 / 면접 |
| 속성 값 | 속성 id별 값, 기본은 없음 |
| 전형 일정 목록 | 아래 "전형 일정" 여러 개 |
| 본문 | 마크다운 텍스트 |
| 만든 날, 고친 날 | 날짜·시간 |

**전형 일정**: 종류(지원 완료 / 과제 마감 / 코딩테스트 / 면접), 날짜, 시간(선택), 메모(선택)

**속성 정의 (모든 카드가 공유)**: id, 이름, 종류(7가지), 순서, 선택 항목 목록(항목 이름 + 색), 기본 속성 여부

**기본 속성**
| 속성 | 종류 | 처음 들어 있는 항목 |
|---|---|---|
| 결과 | 선택 | 최종 합격 / 불합격 / 지원 포기 |
| 회사 | 선택 | 없음 (쓰면서 추가) |
| 직무 | 선택 | 없음 (쓰면서 추가) |
| 공고 링크 | URL | - |
| 마감일 | 날짜 | - |
| 지원일 | 날짜 | - |
| 우선순위 | 선택 | 높음 / 중간 / 낮음 |
| 제출 자료 | 다중 선택 | 이력서 / 자기소개서 / 포트폴리오 PDF / 포트폴리오 Notion / 기술 소개서 / GitHub / 과제 결과물 |
| 경력 구분 | 선택 | 신입 / 경력 / 무관 |
| 고용 형태 | 선택 | 정규직 / 계약직 / 인턴 / 전환형 인턴 |

**저장 위치**: 이번에는 PC에만 저장한다(개발 순서 1단계). 붙여 넣은 이미지는 앱 데이터 폴더에 파일로 저장한다. 구체적인 저장 방식은 구현 계획에서 정한다.

**상태 색**: 홈에서 쓰는 색(회색·파랑·주황·초록)을 이어서 쓴다. 상태별 색 배정은 목업에서 정한다. (→ 정함, 위 "목업에서 정한 것" 참고)

## 이번 범위에서 제외하는 것
- 상세 창을 OS 창으로 따로 띄우기
- 상태 목록 편집
- 댓글 영역
- 지원 경로 속성
- 달력 주 단위 보기, 달력에서 날짜를 눌러 일정 추가
- 카드 순서를 끌어서 바꾸기, 정렬 방식 바꾸기, 필터
- 검색
- 본문 이미지 크기 조절
- Supabase 동기화, 여러 기기 사용

## 나중에 고려할 것
- 캘린더 계획 기능과 지원 일정 연동
- 달력 페이지에서 바로 일정 추가
- 검색, 속성별 필터·정렬
- 본문 템플릿 (공고 내용 / 자소서 메모 / 면접 질문 틀)
- Supabase 동기화와 이미지 저장소 이전
- 공유 웹(친구용 지원 현황 페이지)에 노출
- 일정 알림 (예: 코딩테스트 하루 전)

| 갤러리 열 수 | 4열, 창 폭이 좁으면 3열 |

### 목업에 넣은 추가 제안 (목업과 함께 승인)
- D-1·당일 일정은 D-day를 빨간색으로 표시
- 카드에 남은 일정이 없으면 "예정된 일정 없음"을 흐리게 표시 (팝업의 📅 옆은 R24대로 비워 둠)
- 팝업 바깥(어두운 부분)을 누르면 닫힘
- 달력 하루 칸에 일정이 3개를 넘으면 "+N개 더"로 접음

## 결정 사항
형식: `D번호. 내용 (적용: 계획 단계 범위) (기록: L번호)`. 노트의 "관련 결정"에 적힌 번호의 줄만 읽으면 된다.
- D1. 작은 창은 공용 `Popover`(+`useOutsideLayer`)와 `MiniCalendar`를 쓴다. (적용: 5~8단계) (기록: L07)
- D2. 팝업과 작은 창은 `AppLayout`의 겹침 층(`OverlayRootContext`)에 그리고, 제목 표시줄은 덮지 않는다. (적용: 이후 전체) (기록: L06)
- D3. 상태를 바꿀 때의 규칙(R20~R22)은 `features/applications/transitions.ts`의 순수 함수로 둔다. (적용: 5단계) (기록: L03)
- D4. 역할 속성(지원일·결과 등)은 `findPropertyByRole`로 찾고, 지워졌으면 그 속성에 기대는 기능(자동 입력, 결과 칸 등)은 건너뛴다. (적용: 이후 전체) (기록: L05, L07)
- D5. 상세 팝업은 열 때마다 기본 크기로 시작하고, 새 카드를 만들어도 자동으로 열지 않으며, 포커스 가두기는 하지 않는다. (적용: 이후 전체) (기록: L06)
- D6. 속성 편집: 빈 이름은 저장하지 않고, 종류 변경은 확인 없이 바로, 항목·속성 삭제는 항상 확인 창을 띄우며, 지운 역할 속성은 다시 만들 수 없다. (적용: 이후 전체) (기록: L07)
- D7. 달력 칸 계산은 공용 `utils/calendarGrid.ts`를 쓴다. (적용: 8단계) (기록: L07)
- D8. 숫자 속성은 쉼표를 빼고 저장·표시한다. (적용: 이후 전체) (기록: L07)
- D9. 결과 칩은 `properties/OptionChip`, 상태 배지는 기존 `status/StatusBadge`를 큰 크기로 확장해서 쓴다. (적용: 5단계) (기록: L05, L07)
- D10. 개발 환경: 1420 포트가 막히면 남은 Vite 서버를 먼저 끄고, 미리보기는 `desktop-web-alt`(1430)를 쓴다. (적용: 이후 전체) (기록: L06)
- D11. 저장: 창을 닫을 때 기다리던 저장을 바로 쓰고 닫으며, 저장 파일이 깨졌으면 저장을 막는다. (적용: 이후 전체) (기록: L04)

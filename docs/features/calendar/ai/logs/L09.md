# L09 · 2026-11-05 · 구현 6단계: 드래그로 옮기기

- 요구사항: R35–R40
- 한 일: `drag/useCalendarDrag`가 주 줄 칩의 mousedown에서 시작해 4px 넘게 움직이면 드래그로 바꾼다. 태스크·개인 칩은 원래 자리 28%, `DragGhost`(body 포털, -1.5°, 큰 그림자)가 포인터를 따라가고, 놓일 기간의 칸은 옅은 보라 바탕 + 테두리(`cal-day--drop`), 주마다 빈 줄에 보라 점선 자리(`cal-drop-slot`)를 그린다. 놓으면 (놓은 날 − 잡은 날)만큼 태스크는 `updateTask(moveBy)`(완료 포함), 개인 일정은 `moveEvent`로 옮기고 새 칩이 280ms 튀어오른다. 지원·깃발은 4px 넘게 끌면 260ms 좌우로 흔들리기만 한다. 그리드 밖에 놓거나 Esc → 취소. 드래그·흔들림 뒤 따라오는 click은 한 번 삼켜 창이 열리지 않는다. 끝 손잡이는 없다(R38).
- 결정: D16 추가 (칩 드래그 연결 방식, 칸 찾기, click 삼키기)
- 계획과 달라진 점: (자동 진행 중 판단) 포인터 아래 칸은 `data-day` 대신 `useRangeSelect`의 `dayAt`(D15)을 export해 같이 쓴다. 드래그 시작은 포인터 이벤트가 아니라 mousedown(D15와 같은 이유). 훅은 `CalendarPage`가 아니라 `MonthGrid`에 두어 `CalendarPage.tsx`·`Chips.css`는 고치지 않았고, 칩 모양 CSS는 `drag/Drag.css`에 모았다. 칩 4종(`TaskChip`·`AppChip`·`FlagChip`·`PersonalChip`)에 `onMouseDown`을 넘기고(`ChipFrameProps`에 선택 항목 추가), `grid/DayCell.tsx`에 `drop` 칸 표시를 더했다. +N 목록 안 칩은 끌 수 없다(누르기만). +N 목록·편집 팝오버가 열려 있으면 칩 mousedown은 `useOutsideLayer`가 막아 창만 닫히므로 드래그 중에 열려 있을 수 없다.
- 확인: `npm run build` 성공 (tsc 포함), `npx tsc --noEmit` 통과. 화면 확인은 하지 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 점선 자리는 놓일 칸들의 빈 줄에 놓여 다 찼으면 마지막 줄을 덮는다. 같은 칸에 도로 놓으면 아무 일도 없다(튀어오름도 없음). 주 경계를 넘는 막대를 놓으면 두 주의 조각이 함께 튀어오른다.

# L06 · 2026-11-05 · 구현 3단계: 칩 4종과 칸 배치

- 요구사항: R8–R18, R20
- 한 일: `items.ts`가 플랜 태스크(날짜 있는 것, 묶음 색)·지원 일정(`groupEntriesByDate` + `companyName`, 배지)·깃발(`checkpoints.ts`, 주차형만 일요일)·개인 일정을 보이는 기간(그리드 첫날~끝날)으로 걸러 `CalItem`으로 모은다. `badge.ts`는 첫 글자와 해시 % 7 + 1 색 번호. `monthLayout.ts`의 `layoutWeek`가 주마다 막대 줄 → 하루짜리(시간순 → 태스크·지원·깃발·개인) 자리와 +N을 계산한다. `MonthPage`가 세 저장소를 읽어 주마다 `WeekLayout`을 넘기고, `WeekRow`가 `CalChip`(태스크·지원·깃발·개인 칩)과 "+N" 글자를 `.cal-week` 그리드 2~5행에 놓는다. 아이콘은 `CalendarIcons.tsx`(`AppKindIcon`·`FlagIcon`).
- 결정: D13 추가 (넘침 판정·+N 수·목록 순서)
- 계획과 달라진 점: (자동 진행 중 판단) 넘침은 "항목 5개 이상" 대신 "그날 필요한 줄 수가 4를 넘을 때"로 판정하고, +N은 숨긴 칩 수로 센다(막대 줄 사이에 빈 줄이 있는 날도 칩이 4줄 밖으로 나가지 않게. 빈 줄이 없으면 계획과 같다). `CalItem`의 태스크·개인 일정에 줄 순서용 `createdAt`을 더했다. "+N"은 이번 단계에서는 글자만 그리고 누르기·목록은 4단계에서 붙인다. 깃발 마우스 올림은 목업 CSS대로 회색 바탕 + 1px 뜸·그림자.
- 확인: `npm run build` 성공 (타입 검사 포함). rolldown으로 묶어 Node로 `layoutWeek` 실행: (a) 화요일 줄 순서 막대 → 14:00 지원 → 시간 없는 태스크, (b) 하루짜리 6개 → 3개 + "+3", (c) 월~금 4번째 줄 막대가 넘친 수요일에서 월·화(오른쪽 잘림)와 목·금(왼쪽 잘림) 두 조각, 주 경계 막대는 양쪽 잘림. 화면 확인은 하지 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 양쪽이 다 잘린 막대(앞 주에서 시작해 다음 주로 이어지는 태스크)가 두 끝 모두 옅어지는지 본다. 회사 이름이 없는 카드는 카드 제목 첫 글자 배지로 나오는지 본다.

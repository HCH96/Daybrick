# 캘린더 결정 사항

- D1. 스케줄러 메뉴를 없애고 캘린더로 대신한다. 메인 페이지 D1("캘린더와 스케줄러를 따로 둔다")을 대신한다. (적용: 이후 전체) (기록: L01)
- D2. 드래그로 옮길 수 있는 것은 태스크와 개인 일정뿐이다. 지원 일정과 체크포인트는 원래 화면에서만 바꾼다. (적용: 이후 전체) (기록: L01)
- D3. 회사 로고는 회사 이름 이니셜 배지로 대신하고, 인터넷 요청을 하지 않는다. (적용: 이후 전체) (기록: L01)
- D4. 체크포인트는 주차형 프로젝트 주차의 일요일에만 꽂는다. (적용: 이후 전체) (기록: L01)
- D5. 지난 날짜를 누르면 회고, 오늘과 미래 날짜를 누르면 입력이다. (적용: 이후 전체) (기록: L01)
- D6. 이번 작업에서 홈 화면은 바꾸지 않는다. 메뉴 id가 바뀌어서 이동 버튼이 가는 곳만 고친다. (적용: 이후 전체) (기록: L01)
- D7. 개인 일정은 앱 데이터 폴더의 `calendar.json`(`{ version: 1, events }`)에 저장하고, Rust `calendar.rs`의 load_calendar·save_calendar로 읽고 쓴다. 플랜도 개인 일정을 보므로 `CalendarProvider`는 `PlanProvider` 안에 둔다. (적용: 이후 전체) (기록: L03)
- D8. 달력 칸은 4줄이다. 여러 날 막대 줄 → 시간 있는 하루짜리(시간순) → 시간 없는 하루짜리(태스크 → 지원 → 깃발 → 개인) 순으로 놓는다. 그날 항목이 5개 이상이면 1–3줄만 보이고 4번째 줄은 "+N"이며, 4번째 줄을 지나는 막대는 넘친 날에서 끊어 그린다. (적용: 3단계 이후) (기록: L03)
- D9. 개인 일정 편집에서 시작일을 끝일 뒤로 바꾸면 끝일이 시작일로 따라오고, 끝일을 시작일 앞으로 고르면 빨간 안내와 함께 [저장]을 막는다. (적용: 5단계 이후) (기록: L03)
- D10. 캘린더 드래그는 포인터 이벤트로 직접 만든다. 4px 넘게 움직여야 드래그이고, 빈 칸에서 시작하면 기간 입력, 칩에서 시작하면 옮기기다. (적용: 5단계 이후) (기록: L03)
- D11. `window.__calendar` 개발용 노출은 9단계에서 없앴다. 5단계부터 입력 화면이 있어 개인 일정은 화면에서 넣는다. (적용: 이후 전체) (기록: L04) (L12에서 변경)
- D12. 주 줄(`WeekRow`의 `.cal-week`)은 7열 × (28px 날짜 자리 + 21px 칩 줄 4) 그리드다. 뒤에 절대 위치 `.cal-week__bg`를 깔고 그 안의 `DayCell` 7개가 칸 배경과 날짜 숫자를 함께 그린다. 칩은 `.cal-week` 그리드 2~5행에 열·폭으로 직접 놓는다. 달 넘김은 `MonthGrid`가 밀려나는 앞 달 page(`.cal-page--out-*`)를 잠깐 겹쳐 그리고, 넘기는 중에 또 넘기면 그 page를 버린다. (적용: 3단계 이후) (기록: L05)
- D13. 달력 칸의 넘침은 그날 필요한 칩 줄 수(그날을 지나는 가장 아래 막대 줄 + 하루짜리 수)가 4를 넘을 때다. 넘치면 1–3줄만 보이고, "+N"의 N은 그날 숨긴 칩 수다. `WeekLayout.more[].items`는 그날 칩 전부를 칸과 같은 순서(막대 줄 순 → 하루짜리 순)로 담아 +N 목록이 그대로 쓴다. (적용: 3단계 이후) (기록: L06)
- D14. 칩 누르기는 `CalendarPage`의 `openItem`(`CalOpenHandler`, 칩 종류별로 여는 창을 정함)을 `MonthGrid → MonthPage → WeekRow → CalChip·MoreButton`으로 내려 보낸다. 칩 4종은 `ItemChip`(`ChipFrameProps`의 className·style·onClick·children)이 달력 칸과 +N 목록에서 함께 그린다. 지원관리 달력 CSS(`CalendarView.css`의 `.cal-more`·`.cal-more-pop` 등)와 이름이 겹치지 않게 +N은 `.cal-week-more`, 목록은 `.cal-day-list`를 쓴다. (적용: 4단계 이후) (기록: L07)
- D15. 달력 빈 곳 누르기·기간 드래그(`grid/useRangeSelect`)는 `.cal-pages`의 mousedown으로 시작하고 window의 mousemove·mouseup으로 따라간다. 작은 창이 열린 채 바깥을 누르면 `useOutsideLayer`가 mousedown을 막아, 창을 닫는 누름이 입력으로 이어지지 않게 하려는 것이다. 칸은 `.cal-week[data-week]`(그 주 월요일) 너비를 7로 나눠 찾고, `.cal-chip`·`.cal-week-more`·`.cal-pin`(입력칸)에서는 시작하지 않는다. 입력 중인 새 일정(`PersonalDraft`)은 `MonthGrid`가 들고, `CalOpenHandler`는 `(item, anchor)`로 누른 칩(+N 목록이면 "+N")을 넘긴다. (적용: 5단계 이후) (기록: L08)
- D16. 칩 옮기기(`drag/useCalendarDrag`)는 `MonthGrid`가 들고, `ChipDrag`(onChipDown·dragKey·bounceKey·shakeKey)를 `MonthPage → WeekRow → CalChip`으로 내려 보낸다(밀려나는 달 page와 +N 목록 칩에는 없음). 칩 mousedown으로 시작해 window mousemove·mouseup·Esc로 따라가고, 칸은 `useRangeSelect`의 `dayAt`(D15)으로 찾는다. 4px 넘게 움직였으면(흔들림·Esc 취소 포함) 뒤따르는 click을 window capture에서 한 번 삼킨다. 놓일 기간은 `drop`으로 `DayCell`(`cal-day--drop`)과 `WeekRow`(`cal-drop-slot`)에 넘긴다. (적용: 6단계 이후) (기록: L09)
- D17. 회고 패널은 `CalendarPage`가 `reviewDay`(고른 지난 날)를 들고, `MonthGrid`의 `onReview(day)`(지난 칸 빈 곳 누르기)로 바꾼다. 고른 칸 표시는 `MonthPage → WeekRow → DayCell`의 `reviewDay`/`reviewed`(`cal-day--review`)로 내려 보낸다. 달력과 패널은 `.calendar-page__row`로 나란히 두고, 패널이 열리면 `--review`가 붙어 CSS로 면접 외 지원 종류 아이콘을 숨긴다(칩 컴포넌트는 그대로). 패널 내용은 순수 함수 `features/calendar/review.ts`의 `buildReview`가 만들고, 패널 안 칩은 `ItemChip` + `CalOpenHandler`로 누르기만 한다. (적용: 7단계 이후) (기록: L10)
- D18. 플랜 주간 달력의 개인 일정은 `pages/plan/calendar/PersonalLayer.tsx` 층(지원 일정 층 아래·막대 층 위, `.plan-personal`)이 그린다. `WeekCalendar`가 `buildCalItems`(plan·applications null)로 이번 주 개인 일정을 모아 넘기고, 막대 줄은 `monthLayout`에서 export한 `layoutBars`·`compareSingles`로 정한다. 칩 모양은 `WeekCalendar.css`의 `.plan-pev`(캘린더 `.cal-chip--personal`과 같은 값)이고, 시간 없는 일정이 덮는 날은 `.plan-cols__busy`다. 플랜 쪽에서는 끌지 않고 누르면 `PersonalEditPopover`만 연다. (적용: 8단계 이후) (기록: L11)
- D19. 지원관리 달력(`pages/applications/calendar/CalendarView.css`)의 `.cal-week`·`.cal-day`·`.cal-day__num`·`.cal-day--*` 규칙은 `.cal-view` 안으로 묶는다. 캘린더 페이지가 같은 이름을 쓰므로, 지원관리 달력 CSS에 새 `.cal-*` 규칙을 넣을 때도 `.cal-view`로 묶는다. (적용: 이후 전체) (기록: L12)

# 캘린더 결정 사항

- D1. 스케줄러 메뉴를 없애고 캘린더로 대신한다. 메인 페이지 D1("캘린더와 스케줄러를 따로 둔다")을 대신한다. (적용: 이후 전체) (기록: L01)
- D2. 드래그로 옮길 수 있는 것은 태스크와 개인 일정뿐이다. 지원 일정과 체크포인트는 원래 화면에서만 바꾼다. (적용: 이후 전체) (기록: L01)
- D3. 회사 로고는 회사 이름 이니셜 배지로 대신하고, 인터넷 요청을 하지 않는다. (적용: 이후 전체) (기록: L01)
- D4. 체크포인트는 주차형 프로젝트 주차의 일요일에만 꽂는다. (적용: 이후 전체) (기록: L01)
- D5. 지난 날짜를 누르면 회고, 오늘과 미래 날짜를 누르면 입력이다. (적용: 이후 전체) (기록: L01)
- D6. 이번 작업에서 홈 화면은 바꾸지 않는다. 메뉴 id가 바뀌어서 이동 버튼이 가는 곳만 고친다. (적용: 이후 전체) (기록: L01)
- D7. 개인 일정은 앱 데이터 폴더의 `calendar.json`(`{ version: 1, events }`)에 저장하고, Rust `calendar.rs`의 load_calendar·save_calendar로 읽고 쓴다. 플랜도 개인 일정을 보므로 `CalendarProvider`는 `PlanProvider` 안에 둔다. (적용: 이후 전체) (기록: L03)
- D8. 달력 칸은 4줄이다. 여러 날 막대 줄 → 시간 있는 하루짜리(시간순) → 시간 없는 하루짜리(태스크 → 지원 → 깃발 → 개인) 순으로 놓는다. 그날 항목이 5개 이상이면 1–3줄만 보이고 4번째 줄은 "+N"이며, 4번째 줄을 지나는 막대는 넘친 날에서 끊어 그린다. (적용: 3단계 이후) (기록: L03)
- D9. 개인 일정 편집에서 시작일을 끝일 뒤로 바꾸면 끝일이 시작일로 따라오고, 끝일을 시작일 앞으로 고르면 빨간 안내와 함께 [저장]을 막는다. (적용: 5단계 이후) (기록: L03)
- D10. 캘린더 드래그는 포인터 이벤트로 직접 만든다. 4px 넘게 움직여야 드래그이고, 빈 칸에서 시작하면 기간 입력, 칩에서 시작하면 옮기기다. (적용: 5단계 이후) (기록: L03)

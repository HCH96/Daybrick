# L11 · 2026-10-27 · 구현 8단계: 서버 확인 기록·오프라인

- 요구사항: R33
- 한 일: `serverSync.ts`에 `writeReadState(client, ids, readAt)`(여러 행의 `read_at`을 한 번에 update)를 더했다.
- 새 `pendingAcks.ts`: `addPending`(같은 id는 마지막만), `applyPending`(대기 기록 우선), `removeSent`(보낸 기록만 지움, 그 사이 새 기록은 남김), `flushPending`(같은 readAt끼리 묶어 앞에서부터 쓰고, 실패하면 멈추고 성공한 것만 돌려줌).
- reducer: 확인 동작 세 개가 `local`과 `serverCopy`를 함께 바꾸고, 서버 사본에서 바뀐 알림을 `pendingAcks`에 쌓는다. `server-loaded`·`server-upsert`에 `applyPending`을 적용하고 `acks-sent`를 더했다. `mark-unread`에도 시각(`now`)을 넣는다.
- `useServerNotifications`: 연결되면 대기 기록을 먼저 쓰고 그다음 받는다. 연결된 동안 대기 기록이 바뀌면 바로 쓴다(쓰는 중이면 끝난 뒤 한 번 더). `pendingAcks`는 기존 자동 저장으로 파일에 남아 앱을 다시 켜도 반영된다.
- 결정: D16 추가
- 계획과 달라진 점: 계획은 "쓰기가 실패하면 pendingAcks에 넣는다"였으나, 먼저 넣고 성공하면 지우는 방식으로 했다. 쓰는 도중 앱이 꺼져도 기록이 남게 하려는 것이고 보이는 동작은 같다 (자동 진행 중 판단).
- 확인: `npm run build`(타입 검사 포함) 성공. 실제 서버 쓰기·오프라인 반영은 실행해 보지 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 연결된 상태에서도 확인 직후 잠깐 `notifications.json`의 `pendingAcks`에 기록이 있다가 쓰기가 끝나면 비워진다. 와이파이를 꺼도 서버 상태가 아직 "연결됨"이면 쓰기 실패로 남았다가, 다음 확인 동작이나 다시 연결될 때 반영된다.
- 주요 파일: apps/desktop/src/features/notifications/pendingAcks.ts, reducer.ts, useServerNotifications.ts, serverSync.ts

# L08 · 2026-10-27 · 구현 5단계: 갈 곳 이동

- 요구사항: R16, R17, R25
- 한 일: `app/pageIntent.tsx`를 만들었다. `PageIntentProvider`가 요청 하나를 ref에 맡아 두고(꺼낼 때 바로 비워 StrictMode에서도 한 번만 꺼냄), `openTarget`은 `pages`에 없는 페이지면 false, 있으면 요청을 맡기고 `navigate` 후 true. `usePageIntent(pageId, handler)`는 마운트·새 요청 때 자기 요청을 꺼내 넘긴다. 이번에는 쓰는 화면이 없다.
- `App.tsx`에서 Provider는 `AppScreens`의 `main`(AppLayout)만 감싼다 (NavigationContext 안, TitleBar 바깥). 전체 화면에는 Provider가 없어 이동할 수 없다.
- 행 본문 누르기: 안 읽은 알림이면 `handleMarkRead`(안 읽음 필터 흐리게 남기기 포함) → 갈 곳이 있고 `openTarget`이 true면 패널 닫기. 행에 `cursor: pointer`를 줬다. `extension.md`의 "갈 곳 처리"를 확정된 방법과 예시로 고쳤다.
- 결정: D13 추가
- 계획과 달라진 점: `openTarget`을 Context 값 대신 `useOpenTarget()` 훅으로 꺼내 쓰고, `findPage`(없으면 예외)는 고치지 않고 `pages.find`로 확인했다 (자동 진행 중 판단).
- 확인: `npm run build`(타입 검사 포함) 성공. Rust는 고치지 않았다. 앱을 띄워 화면을 보지는 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 이미 확인한 알림의 본문을 누르면 확인 상태는 그대로이고 갈 곳이 있으면 이동한다. 연결 마법사 화면에서 알림을 누르면 이동 없이 확인만 된다.
- 주요 파일: apps/desktop/src/app/pageIntent.tsx, App.tsx, components/notifications/NotificationPanel.tsx, NotificationRow.tsx

# 구직 관리 요구사항: 공고 수집 (R33–R40, R82)

### 공고 수집
- R33. 서버가 일주일에 한 번(기본: 월요일 오전 6시) 켜진 모든 사이트를 수집한다.
- R34. 수집 사이트 탭의 "지금 수집" 버튼으로 바로 수집할 수 있다.
- R35. 같은 사이트 안에서는 공고 고유 id(없으면 주소)가 같으면 같은 공고로 본다. 사이트가 다르면 회사 이름이 같고 아래 규칙으로 정리한 제목이 같을 때 같은 공고로 본다. (L33에서 변경)

| 정리 규칙 (다른 사이트 판정 키) | 예 |
|---|---|
| 공백·기호를 지우고 소문자로, 회사의 법인 표기(주식회사, (주), ㈜, 유한회사)를 뺀다 | (기존과 같음) |
| 제목 앞뒤의 말머리 `[…]`, `(…)`를 뺀다 | `[스마일게이트RPG] 클라이언트` → `클라이언트` |
| 상투어를 뺀다: 채용, 모집, 신입, 경력, 신입/경력, 정규직, 계약직, 상반기, 하반기, 수시, 공채 | `서버 개발자 경력 채용` → `서버 개발자` |
| 제목 안에 들어간 회사 이름을 뺀다 | `스마일게이트 서버 개발자` → `서버 개발자` |

- R36. 사이트에서 읽은 공고가 0개이거나, 필수 항목(제목·링크)이 빠진 공고가 절반을 넘으면 "수집 실패"로 기록하고 알림을 보낸다.
- R37. 같은 사이트에 연달아 요청할 때는 간격을 둔다.
- R38. 공고 본문이 이미지이면 이미지를 비공개 저장소에 저장한다.
- R39. 수집한 원문(텍스트·이미지)은 저장해 두고 다시 내려받지 않는다.
- R40. 수집이 끝나면 새 공고를 처리 순서(R41)로 넘기고, 일괄 처리(R102)로 맡긴다. (L44에서 변경)
- R82. 수집 단계에서 다른 사이트의 공고와 같다고 판정되면(R35), 버리지 않고 기존 공고에 묶인 중복(R85)으로 저장한다. 원문은 받지 않고 AI 처리도 하지 않는다. 대표가 바뀌면(R87) 원문만 받는다.

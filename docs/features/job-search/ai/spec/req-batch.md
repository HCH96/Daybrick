# 구직 관리 요구사항: 일괄 처리 (R102–R110)
주간 처리의 추출·채점을 Anthropic Batch API로 한 번에 맡긴다. 처리 순서는 R41, 한도는 R73–R74.

### 일괄 처리
- R102. 주간 수집(자동·"지금 수집")이 끝나면 처리할 공고를 Anthropic Batch API로 한 번에 맡긴다.
- R103. 일괄 처리는 두 번 맡긴다. 추출 일괄의 결과가 오면 중복 확인·2차 필터를 AI 없이 하고(애매한 쌍은 R113), 통과한 공고를 채점 일괄로 맡긴다. 결과가 오면 저장하고 끝낸다.
- R104. 예약 확인이 맡긴 일괄 작업이 끝났는지 보고, 끝났으면 결과를 저장하고 다음 단계로 넘긴다. 맡긴 작업이 없고 처리할 공고도 없으면 서버 함수를 부르지 않는다.
- R105. 추천 공고 탭과 수집 사이트 탭의 처리 상태 줄에 일괄 처리 상태를 보여준다 (예: "일괄 처리 중: 채점 120개 맡김 · 10/30 06:12").
- R106. [지금 평가]는 이름을 그대로 두고, 대기 중인 공고를 바로 일괄 처리로 맡긴다. 맡긴 작업이 진행 중이면 끝날 때까지 꺼 둔다.
- R107. 공고 하나에 대한 버튼([그래도 채점], [다시 채점])과 프로필 만들기·메일 분류는 지금처럼 바로 호출한다.
- R108. 일괄 작업 안에서 실패하거나 만료된 항목은 대기 상태로 되돌려 다음 일괄 처리에 다시 넣는다. 거절(인젝션·정책)된 항목은 지금처럼 실패(failed)로 둔다.
- R109. 이미 추출·채점된 공고는 다시 맡기지 않는다 (R53).
- R110. 일괄 처리 비용은 할인 단가로 계산해 기록한다. 맡기기 전에 예상 비용을 계산하고, 이번 달 한도를 넘으면 넘지 않는 만큼만 맡기고 나머지는 대기로 둔다.

# 구직 관리 요구사항: 중복 공고 묶기 (R83–R89)
다른 사이트에 올라온 같은 공고를 대표 하나로 묶는다. 수집 단계의 판정은 R35·R82, 화면 표시는 R91–R93([req-recommend.md](req-recommend.md)).

### 중복 확인
- R83. 항목 추출 뒤·2차 필터 전에 "중복 확인"을 한다(R41). 비교 대상은 다른 사이트에서 들어와 추출이 끝난 공고이고, 걸러진·숨긴·지원한 공고도 포함하며 마감이 지난 공고는 뺀다.
- R84. 아래 조건을 모두 만족할 때만 같은 공고로 본다(엄격 판정). 애매하면 묶지 않는다.

| 조건 | 기준 |
|---|---|
| 회사 | 정리한 회사 이름이 같거나, 한쪽이 다른 쪽으로 시작한다 (예: 스마일게이트 / 스마일게이트RPG) |
| 마감일 | 정리한 마감일이 같거나, 둘 다 없다(상시) |
| 직무·제목 | 정리한 제목(R35 규칙)이나 추출한 직무가 충분히 비슷하다. 정확한 기준은 계획 단계에서 정하고 엄격한 쪽으로 둔다 |

### 묶기와 대표
- R85. 같은 공고로 판정된 공고는 지우지 않고 "중복, 대표는 ○○"로 대표 공고에 묶는다. 묶인 공고는 채점하지 않고 모든 목록에서 뺀다.
- R86. 대표는 자사 채용 사이트(R90)의 공고를 우선하고, 둘 다 자사이거나 둘 다 아니면 먼저 수집된 공고로 한다.
- R87. 대표보다 우선하는 공고(예: 게임잡이 대표인데 자사 공고가 들어옴)가 나중에 들어오면 대표를 그 공고로 바꾼다. 원문과 링크는 새 대표의 것을 보여주고, 추출 항목과 점수는 기존 것을 그대로 써서 다시 채점하지 않는다. 지원한 묶음은 대표를 바꾸지 않는다.
- R88. 숨긴(지원 안 함) 공고나 지원한 공고에 묶이면 출처만 더해지고 추천 목록에 다시 나오지 않는다(R16과 같은 취지).
- R89. 서버 업데이트 뒤 한 번, 이미 모아 둔 공고끼리 R84로 비교해 묶는다. 대표는 채점 결과가 있는 공고를 먼저 고르고, 그다음 R86을 따른다.

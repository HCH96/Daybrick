# 구직 관리: 결정 사항

- D1. 지원 관리 카드는 로컬에 두고, 구직 관리가 만든 지원 건의 요약만 서버에 둔다. (적용: 이후 전체) (기록: L01)
- D2. 지원 상태는 지원 관리의 기존 5단계를 그대로 쓴다. (적용: 이후 전체) (기록: L01)
- D3. Gmail은 OAuth 읽기 전용으로 연결하고, 토큰은 서버에 암호화해 저장하며, 하루 한 번 확인한다. (적용: 이후 전체) (기록: L01)
- D4. 서버 연결·설정은 별도 기능 server-setup으로 먼저 만든다. (적용: 이후 전체) (기록: L01)
- D5. Haiku 5.5는 분류·추출·인젝션 검사, Opus 5.5는 채점·프로필 생성을 맡고, 제공자는 Claude만 쓴다. (적용: 이후 전체) (기록: L01)
- D6. AI 한도(하루 100회, 월 $10)는 서버 함수에서 검사한다. (적용: 이후 전체) (기록: L01)
- D7. 남은 크레딧은 조회하지 않고, 기준 잔액을 입력받아 기준 이후 사용액을 빼서 예상 잔액을 보여준다. (적용: 이후 전체) (기록: L01)
- D8. 알림 센터는 별도 기능 notifications로 만들고, 구직 관리는 알림을 보내기만 한다. (적용: 이후 전체) (기록: L01)
- D9. 어댑터는 규칙 파일(JSON)로 만들고 공용 수집 함수가 실행한다. (적용: 이후 전체) (기록: L01)
- D10. 커스텀 필터는 정해진 조건의 조합으로 만들고 AI를 쓰지 않는다. (적용: 이후 전체) (기록: L01)
- D11. "지원 안 함" 공고는 숨기고 보관함에 두며, 다시 수집되어도 추천에 나오지 않는다. (적용: 이후 전체) (기록: L01)
- D12. 자소서 초안 기능은 뺀다. (적용: 이후 전체) (기록: L01)
- D13. Gmail 연결은 server-setup의 Google 클라이언트와 로그인한 계정을 그대로 쓰고, 권한만 추가로 받는다. (적용: 이후 전체) (기록: L02)
- D14. 구직 관리 서버 테이블은 `js_` 접두어를 붙이고 본인 행만 읽고 쓰게 한다(RLS, `js_gmail_tokens`는 서비스 역할만). 이미지·자료는 비공개 버킷 `job-search`의 `<user_id>/` 아래. 서버 구조 3번은 테이블, 4번은 예약 실행. (적용: 이후 전체) (기록: L04)
- D15. 서버 함수는 `js-profile`·`js-collect`·`js-process`·`js-gmail` 4개, 공용 코드는 `_shared/`. 모든 AI 호출은 `_shared/ai.ts`를 거쳐 한도 검사·호출 기록을 한다. (적용: 3단계 이후) (기록: L04)
- D16. 어댑터 규칙 형식 v1은 plan/structure.md 3절(`format`·`vars`·`delayMs`·`list`·`detail`)을 따르고, HTML은 CSS 선택자로 읽는다. (적용: 5단계 이후) (기록: L04)
- D17. `js-process`는 한 번에 정해진 개수(기본 5)만 처리하고, 남은 공고는 다음 실행이 이어 받는다. (적용: 9단계 이후) (기록: L04)
- D18. Gmail은 앱이 직접 Google 인증(127.0.0.1 수신기 재사용, 로그인 이메일 고정)을 열고, 코드 교환과 갱신 토큰 암호화(`GMAIL_TOKEN_KEY`, AES-GCM)는 `js-gmail`이 한다. 연결 해제 때 Google 권한도 취소한다. (적용: 13단계 이후) (기록: L04)
- D19. 예약 실행은 pg_cron + pg_net이 `x-daybrick-cron` 머리글(`DAYBRICK_CRON_SECRET`, vault에도 저장)로 서버 함수를 부른다. 자동 생성 비밀값은 서버 업데이트·자동 세팅 때 없을 때만 만든다. (적용: 2, 15단계) (기록: L04)
- D20. 지원 관리 카드에 선택 칸 `jobLink: { serverId } | null`을 더하고 파일 버전은 2를 유지한다. (적용: 12단계 이후) (기록: L04)
- D21. 로컬 파일 `job-search.json`에 추천 공고 탭을 마지막으로 연 시각과, 서버에 반영하지 못한 상태 변경 대기 목록을 둔다. (적용: 10단계 이후) (기록: L04)
- D22. 구직 관리 탭 id·이름은 `pages/job-search/tabs.ts` 한 곳에 둔다. 탭을 만드는 단계는 `JobSearchPage`에서 그 탭의 `TabPlaceholder`를 실제 탭 컴포넌트로 바꾼다. (적용: 이후 전체) (기록: L05)
- D23. `js_settings.prices`는 모델 id → `{ input, output, cacheRead, cacheWrite }`(100만 토큰당 달러). 캐시 단가 기본값은 입력의 0.1배(읽기)·1.25배(쓰기)로 넣었다 (Anthropic 캐시 가격 배율과 같음). `js_ai_calls`는 앱이 읽기만 하고 서버 함수(서비스 역할)만 넣는다. (적용: 이후 전체) (기록: L06) (L07에서 변경)
- D24. 자동 생성 비밀값은 32바이트 무작위 값의 16진수 64글자다 (`GMAIL_TOKEN_KEY`도 이 글자를 풀어 AES 키로 쓴다). vault 사본이 있는 비밀값은 함수 비밀값·vault 중 하나라도 없으면 둘 다 새 값으로 맞춘다. 서버 업데이트 단계 목록에 "비밀값 만들기"가 있다. (적용: 이후 전체) (기록: L06)
- D25. AI 사용량의 "오늘"·"이번 달" 경계는 한국 시간(UTC+9)이다 (서버 `_shared/ai.ts`와 앱 `usage.ts`가 같은 계산). Anthropic까지 간 호출은 성공·실패 모두 `js_ai_calls`에 기록하고 하루 호출 수에 센다. 실패한 호출의 비용은 0. (적용: 이후 전체) (기록: L07)
- D26. 서버 함수는 `getCaller(req)`(`_shared/auth.ts`)로 받은 `Caller`를 `callClaude(caller, { task, model, system, content, schema })`에 넘긴다. 결과 JSON은 강제 도구 호출(도구 이름 `result`)로 받고, 결과 종류는 `ok`·`limit`(daily/monthly)·`credit`·`error`. `_shared` 파일은 `migrations.rs`의 `AUTH`·`AI` 상수로 각 js- 함수 `files`에 넣는다 (처음 쓰는 단계에서 `allow(dead_code)`를 지운다). 앱 화면은 `JobSearchProvider`의 `useJobSearch()`로 설정·기록을 읽고, 저장 뒤 `refresh()`를 부른다. (적용: 4단계 이후) (기록: L07)
- D27. 프로필 내용(`js_profiles.data`·`js_profile_drafts.data`)은 앱 `ProfileData`(types.ts)와 서버 `PROFILE_SCHEMA`(`_shared/prompts.ts`)가 같은 모양이다: 글 항목은 `{ value, sources }`(자료에 없으면 null·빈 배열), 기술스택 `{ items: { name, level: high|mid|low }[], sources }`, 경력 `{ title, period, did, results, tech[], sources }[]`. 출처는 넣은 자료 이름만 남긴다. `js_profiles.sources`는 저장할 때 있던 자료 이름 목록, 저장 버전은 가장 큰 버전 + 1, 저장 순서는 버전 행 → `profile_version` → 초안 삭제. 자료 원문은 `<source name kind>` 칸(PDF는 문서 블록 `title`=자료 이름)에 넣는다. `_shared/prompts.ts`는 `migrations.rs`의 `PROMPTS` 상수로 AI를 부르는 js- 함수 `files`에 넣는다. 한도·크레딧 안내 문구는 `messages.ts`의 `aiLimitMessage`·`AI_CREDIT_MESSAGE`를 같이 쓴다. (적용: 이후 전체) (기록: L08)
- D28. 프로필 자료 파일은 Storage `<user_id>/sources/<무작위 uuid>.<pdf|md>`에 두고 원래 이름은 `name` 칸에 둔다 (한글 파일 이름 대비). 파일 하나 10MB, `js-profile`이 보내는 PDF 합계 20MB까지. (적용: 이후 전체) (기록: L08)
- D29. 창 설정 `dragDropEnabled: false`로 웹 화면이 파일 끌어 놓기를 직접 받는다. `app/fileDropGuard.ts`가 받는 곳이 없는 파일 놓기를 창 전체에서 막으므로, 파일을 받는 칸은 `onDragOver`에서 `preventDefault()`를 불러야 한다. (적용: 이후 전체) (기록: L08)

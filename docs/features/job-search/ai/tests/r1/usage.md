- 근거 요구사항: R71, R72
- 수행 방법: `grep "callClaude(|model:|anthropic.com"` (서버·앱 전체). t2-flow에서 callClaude 기록 행과 실제 요청 모델 확인

- 실제 결과: callClaude 호출 4곳 — steps.ts 추출 haiku·채점 opus, js-profile opus, check.ts 메일 haiku. `/v1/messages`를 부르는 곳은 ai.ts 하나. 기록 행 칸은 model·task·input_tokens·output_tokens·cache_read·cache_write·cost_usd·ok, 값이 응답 usage와 같음. 키는 요청 머리글에만 있고 기록 행에 없음
- 판정: 통과
- 참고: `ai-key-check` 함수가 키 확인용으로 `/v1/models`를 직접 부른다. 생성 호출이 아니라 비용·기록 대상은 아니다

## A7 비용 계산
- 테스트 내용: 입력·출력·캐시 읽기·캐시 쓰기 토큰 × 100만 토큰당 단가
- 근거 요구사항: R72, R79
- 수행 방법: t2-flow. 가짜 응답 usage (입력 1000, 출력 500, 캐시 읽기 2000, 캐시 쓰기 400)로 callClaude

- 실제 결과: opus 기본 단가 (1000×4+500×20+2000×0.4+400×5)/1e6 = 0.0168, haiku (1000×0.1+500×0.5+2000×0.01+400×0.125)/1e6 = 0.00042, 설정 단가(문자열 "3" 섞음) 0.0126 — 모두 손계산과 같음. 실패 응답(529)은 cost 0·ok=false로 기록

## A8 한도 검사
- 테스트 내용: 80% 알림, 초과 시 멈춤, 다음 날·달 재개, 기간마다 알림 한 번
- 근거 요구사항: R73, R74
- 수행 방법: t2-flow. 하루 한도 10·월 한도 $1로 기록 행을 미리 넣고 callClaude. `kstBoundaries`에 UTC 14:59:59·15:00 넣기
- 예상 결과: 경계값 맞음
- 실제 결과:
  - 오늘 6회 + 이번 호출 = 7(70%) → 알림 없음 / 7회 + 이번 = 8(80%) → "AI 하루 한도 80% 사용", 다음 호출(9)에는 다시 안 보냄
  - 10회 → Anthropic을 부르지 않고 `limit(daily)`, "AI 하루 한도 초과" 한 번만(두 번 불러도)
  - 어제(한국 시간) 10회 → 오늘은 셈하지 않아 정상 호출, 지난달 $1 → 이번 달 정상
  - 이번 달 $1 → `limit(monthly)` + "AI 월 한도 초과", $0.8 → "AI 월 한도 80% 사용" 한 번
  - UTC 15:00 = 한국 0시로 날짜가 바뀜 (10/27 15:00Z → 10/28 15:00Z), 월 경계도 같음
- 판정: 통과

## A9 기준 잔액
- 테스트 내용: 기준 잔액 이후 합계·예상 잔액, 재입력 시 $0부터
- 근거 요구사항: R75, R76
- 수행 방법: t2-flow에서 앱 usage.ts의 `summarizeUsage`·`balanceHistory` 실행 (기준 $10 10/01, $5 10/20, 호출 4건)
- 예상 결과: 계산 맞음
- 실제 결과: 기준 이후 $1.25, 예상 잔액 $3.75, 이번 달 $3.00(9/30 23시 UTC = 10/1 한국 시간 포함), 오늘 1회. 지금 $20을 다시 넣으면 기준 이후 $0·예상 $20. 입력 기록 표의 옛 기준(10/01) 사용액은 다음 기준 전까지 $1.25. 기준이 없으면 예상 잔액 null
- 판정: 통과

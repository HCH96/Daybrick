# L50 · 2026-10-30 · 구현 수정2 5단계: 일괄 결과 받기·채점 맡기기

- 요구사항: R103, R104, R108, R74, R41 (영향: R53, R80, R83–R89)
- 한 일: step-05대로 했다.
  - 새 `js-process/batchResult.ts` `pollBatches(ctx, deadline)`: 끝난 추출·채점 일괄의 결과를 줄 단위로 저장. 추출은 `saveExtraction` → `routeExtracted`(의심·중복·2차 필터), 채점은 `saveScore`. 거절은 failed, 나머지 실패·만료·취소는 대기로.
  - `index.ts` batch 모드: `pollBatches`(시작 100초까지) → `submitBatches` → 새 추천 알림. 응답에 `saved: { extract, score }`.
  - `steps.ts` `saveScore`에 `toScored`(기본 true) 인자 추가, `migrations.rs` js-process 묶음에 `batchResult.ts`.
- 결정: D81 추가
- 계획과 달라진 점 (자동 진행 중 판단):
  - 새 추천 알림 조건을 "채점 일괄을 저장한 실행" 대신 "결과를 하나라도 저장한 실행"으로 넓혔다. 마지막 일괄이 추출뿐(모두 걸러지거나 점수 재사용)일 때 알림이 빠지지 않게. 보내는 N은 기존 `noticeRecommend` 계산 그대로.
  - 결과가 오기 전에 단계가 바뀐 공고(그 사이 묶임 등)는 단계를 덮어쓰지 않으려고 `saveScore`에 `toScored` 인자를 더했다.
  - 맡기기가 끊긴 행(anthropic_id 없음)은 10분이 지나야 정리한다 (동시에 도는 맡기기를 지우지 않으려고).
- 확인: `npm run build`, `cargo check` 통과. 서버 파일은 tsc(--ignoreConfig, strict)로 타입 검사해 새 파일 오류 없음(외부 모듈 미해결로 생기는 기존 any 오류만 남음). 서버 업데이트·실제 결과 읽기는 하지 않음.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 일괄 결과가 오기 전에 묶인 공고(duplicate)는 채점 결과가 와도 추천에 나오지 않아야 한다. `anthropic_id` 빈 submitted 행은 10분 뒤 다음 batch 실행에서 `failed`가 되고 공고가 다시 맡겨져야 한다.

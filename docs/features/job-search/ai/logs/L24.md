# L24 · 2026-10-28 · 수정: 수집 저장 단계 오류 로그 추가

- 요구사항: R35, R36
- 한 일: 사용자 테스트 r1 4번에서 넥슨이 두 번 다 "공고를 저장하지 못함"으로 실패해 원인을 분석했다.
  이 이유는 `js-collect`의 `saveNew`가 예외를 던질 때만 나온다. 즉 목록은 읽었고, DB 요청 세 개(같은 사이트 ext_id 조회, 다른 사이트 norm_key 조회, 저장) 중 하나가 실패했다. 다만 오류 내용을 버리고 로그도 없어 어느 요청인지 알 수 없었다.
  넥슨 API를 같은 요청으로 직접 불러 보니 1·2쪽은 정상(제목·회사·id 모두 있음, 중복 없음)이고 3쪽부터 HTTP 403이었다. 2쪽 이후 실패는 수집기가 무시하므로 이번 원인은 아니다.
  가장 의심되는 원인(추정): norm_key 조회의 in() 조건이 주소에 들어가는데, 한글 키 40개면 약 7~11KB라 주소 길이 한도를 넘을 수 있다. 게임잡은 같은 경로로 성공해서 확정하지 못했다.
  `saveNew`에 `dbFail`을 넣어 실패한 단계(ext-lookup·norm-key-lookup·insert), 사이트 id, 상태 코드, 오류 코드·메시지·details·hint, 개수와 in() 조건 바이트 수를 `console.error`로 남긴다. DB가 아닌 예외는 `run`의 catch에서 스택을 남긴다. 공고 제목 같은 값은 남기지 않는다.
- 확인: `cargo check` 통과 (함수 파일을 include_str로 묶음). TypeScript transpile로 문법 오류 0개. deno가 없어 함수 자체 타입 검사와 실제 실행은 하지 않음.

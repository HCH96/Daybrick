# L16 · 2026-10-27 · 구현 12단계: 지원하기·일정 제안 (지원 관리 수정)

- 요구사항: R54–R59
- 한 일: 지원 관리 `Application`에 선택 칸 `jobLink`(파일 v2 그대로), reducer `create-from-job`(새 선택 항목+카드를 한 번에), store `createFromJob`·`addEvents`.
- `buildCard.ts`: 공고 → "지원 준비" 카드(회사·직무·공고 링크·경력 구분·고용 형태를 이름으로 찾아 채움, 맞는 선택 항목이 없으면 회색 새 항목), 본문에 자격·우대·적합도 요약·날짜 불명확 일정·원문 링크. `mailDomain`은 공고 링크에서 도메인을 뽑고 채용 플랫폼이면 비운다.
- `scheduleSuggest.ts`: 지원 마감·과제·코딩테스트·면접 중 실제로 있는 날짜만 제안, 나머지는 원문이 있으면 "불명확". `ScheduleSuggestDialog`(600px, 모두 체크된 채 열림, 원문은 일정 메모로).
- [지원하기]: `js_applications` 지원 건 → 로컬 카드 → `applied_at` → 목록 다시 읽기 → 제안할 날짜가 있으면 일정 제안 창, 없으면 팝업을 닫는다.
- `statusSync.ts`: 앱 전체에서 카드 상태 변화를 비교해 서버 지원 건 `status`·`closed`를 고친다(삭제·종료 = closed). 못 보내면 `job-search.json` 대기 목록(지원 건마다 마지막 하나), 연결되면 보낸다. `localState.ts`의 읽고 쓰기를 한 줄로 세웠다.
- 결정: D40 추가
- 계획과 달라진 점: 서버 쓰기는 `api.ts` 대신 새 파일 `applyApi.ts`. 상태 동기화 훅은 `App.tsx`의 `ApplicationsProvider` 안 `JobStatusSync`에서 부른다(지원 관리 화면에서 바꾼 상태를 구직 관리 페이지 밖에서도 받아야 함). 공고 표시(`applied_at`)에 실패하면 일정 제안 창에 경고 줄을 띄운다. 날짜가 정확한 일정이 없으면 창을 띄우지 않는다(목업 메모). (자동 진행 중 판단)
- 확인: `npm run build` 성공. 화면·서버 동작은 실행해 보지 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 처음 보는 회사·직무 이름은 지원 관리 선택 항목에 회색으로 새로 생긴다. 공고 링크가 채용 플랫폼(gamejob 등)이면 `js_applications.domain`이 비어 있다. 앱을 처음 켠 직후(지원 관리 데이터 읽기 전)의 상태 변화는 비교하지 않는다.

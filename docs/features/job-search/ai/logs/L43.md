# L43 · 2026-10-30 · 수정: 서버 함수 배포 실패 원인 조사

- 요구사항: R90 (사용자 테스트 r2 1번 실패 조사)
- 한 일: r2 1번에서 [자동 세팅 다시 실행]이 "서버 함수 배포에 실패"로 계속 멈췄다. 앱이 응답 본문을 버려 이유를 알 수 없어, deploy_functions에 실패 응답(함수 이름·상태 코드·본문)을 터미널에 찍는 임시 로그를 넣고 확인한 뒤 사용자 요청으로 다시 뺐다. 코드 변경은 남지 않았다.
- 결과: 실패 함수는 js-profile(400). Supabase 번들러가 `jsr:@std/encoding/base64`(버전 없음)의 jsr.io meta.json을 10초 안에 받지 못했다. 같은 시각 이 PC에서는 0.4초에 받아졌고, 몇 번 다시 시도하자 배포가 성공했다 → Supabase 빌드 서버와 jsr.io 사이의 일시 문제(앱 코드 문제 아님).
- 결정: @std/encoding을 내장 함수로 바꾸지 않는다. supabase-js 등 다른 jsr 패키지도 같은 문제를 겪을 수 있어 효과가 작다(사용자 판단).
- 확인: 로그 제거 뒤 cargo check 성공(실제 실행).
- 사용자 확인: 완료 (다시 시도로 배포 성공)
- 테스트 메모: 배포가 "예상하지 못한 응답"으로 실패하면 잠시 뒤 다시 시도한다.
- 남은 문제: 체크리스트 1번의 [서버 업데이트]는 실제 버튼 이름 [자동 세팅 다시 실행]으로 고쳐야 한다. Supabase Security Advisor 경고(js_gmail_status 등)는 배포와 무관.

# L09 · 2026-10-27 · 구현 5단계: 규칙 실행기와 수집 함수 (기본 어댑터)

- 요구사항: R25–R27, R35–R40 (R33 예약·R36 알림 연결은 15단계)
- 시작 전 확인: 게임잡은 목록 `POST /Recruit/_GI_Job_List/`(폼 본문, `X-Requested-With` 머리글 필요, 쪽당 40개)와 상세 본문 `GI_Read_Comt_Ifrm?gno=`(대부분 이미지)가 HTML로 읽혔다. robots.txt는 /Recruit/를 막지 않는다. 넥슨은 페이지가 앱 화면이라, 그 화면이 쓰는 공개 JSON `career-gateway.nexon.com/career/v1/open/job-posts`(POST, 목록에 본문 HTML 포함, 총 112개)를 찾았다. careers.nexon.com의 robots.txt는 `/recruit?`만 막고, career-gateway에는 robots.txt가 없다. 두 사이트 이용약관 원문은 확인하지 못했다(개인용·주 1회·요청 간격 1.5초로 진행).
- 한 일: `_shared/adapter.ts`(형식 검사 `validateRule`, 목록 쪽 읽기, HTML 선택자·JSON 경로 칸 뽑기, 상세 본문 글·이미지 주소, 요청 간격), `_shared/dedupe.ts`(ext_id·norm_key), `_shared/notify.ts`(`sendNotice`·합치기 키, 연결은 15단계), `js-collect`(`run`: 사이트별 목록 → 실패 판정 → 새 공고만 저장 → 남은 시간에 원문·이미지 저장, 실행 기록), 기본 어댑터 `adapters/gamejob.json`·`nexon.json`과 `js_ensure_defaults()` RPC(0003), `migrations.rs`에 `js-collect` 묶음(`ADAPTER`·`DEDUPE`, `NOTIFY`는 `allow(dead_code)`).
- 결정: D30, D31 추가
- 계획과 달라진 점: 두 사이트 모두 POST 목록이라 규칙 형식에 `method`·`headers`·`body`, 목록 본문 칸 `fields.body`를 더했다(D30). 함수 시간 한도 때문에 원문은 시간 안에서 받고 나머지는 다음 실행이 이어 받는다(D31). deno-dom은 `jsr:@b-fuze/deno-dom@0.1.56`. (자동 진행 중 판단)
- 확인: `cargo check` 성공, `npm run build` 성공. Deno가 없어 서버 함수 타입 검사·실행은 못 했다. 대신 adapter.ts를 Node(linkedom으로 DOM 대체)로 돌려 게임잡 2쪽 80개(제목·회사·링크·직무 빠짐 0)와 상세 이미지 주소를 읽는 것을 확인했다. 넥슨 목록은 Node fetch에서 403이었고 curl에서는 200이었다 — Edge 함수(Deno)에서 읽히는지는 확인 못 함.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 0003 파일을 고쳤으므로 서버에 구조 3번을 이미 적용했다면 `js_ensure_defaults`가 없다(새 서버나 3번 미적용 서버에서 확인). 확인 전 개발자 도구에서 `rpc("js_ensure_defaults")`로 사이트를 넣는다. 넥슨이 "목록을 읽지 못함 (HTTP 403)"으로 실패하면 기본 어댑터를 어떻게 할지 사용자가 정한다. 첫 실행은 원문을 다 못 받아 `pending`이 남을 수 있다(다시 부르면 이어 받음). 게임잡 이미지 공고는 Storage `postings/`에 저장되는지 본다.

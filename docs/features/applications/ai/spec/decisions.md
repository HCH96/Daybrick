# 지원 관리: 결정 사항

형식: `D번호. 내용 (적용: 계획 단계 범위) (기록: L번호)`.
- D1. 작은 창은 공용 `Popover`(+`useOutsideLayer`)와 `MiniCalendar`를 쓴다. (적용: 5~8단계) (기록: L07)
- D2. 팝업과 작은 창은 `AppLayout`의 겹침 층(`OverlayRootContext`)에 그리고, 제목 표시줄은 덮지 않는다. (적용: 이후 전체) (기록: L06)
- D3. 상태를 바꿀 때의 규칙(R20~R22)은 `features/applications/transitions.ts`의 순수 함수로 둔다. (적용: 5단계) (기록: L03)
- D4. 역할 속성(지원일·결과 등)은 `findPropertyByRole`로 찾고, 지워졌으면 그 속성에 기대는 기능(자동 입력, 결과 칸 등)은 건너뛴다. (적용: 이후 전체) (기록: L05, L07)
- D5. 상세 팝업은 열 때마다 기본 크기로 시작하고, 새 카드를 만들어도 자동으로 열지 않으며, 포커스 가두기는 하지 않는다. (적용: 이후 전체) (기록: L06)
- D6. 속성 편집: 빈 이름은 저장하지 않고, 종류 변경은 확인 없이 바로, 항목·속성 삭제는 항상 확인 창을 띄우며, 지운 역할 속성은 다시 만들 수 없다. (적용: 이후 전체) (기록: L07)
- D7. 달력 칸 계산은 공용 `utils/calendarGrid.ts`를 쓴다. (적용: 8단계) (기록: L07)
- D8. 숫자 속성은 쉼표를 빼고 저장·표시한다. (적용: 이후 전체) (기록: L07)
- D9. 결과 칩은 `properties/OptionChip`, 상태 배지는 기존 `status/StatusBadge`를 큰 크기로 확장해서 쓴다. (적용: 5단계) (기록: L05, L07)
- D10. 개발 환경: 1420 포트가 막히면 남은 Vite 서버를 먼저 끄고, 미리보기는 `desktop-web-alt`(1430)를 쓴다. (적용: 이후 전체) (기록: L06)
- D11. 저장: 창을 닫을 때 기다리던 저장을 바로 쓰고 닫으며, 저장 파일이 깨졌으면 저장을 막는다. (적용: 이후 전체) (기록: L04)
- D12. 카드와 📅 옆의 "다음 일정"(`getNextItem`)에서 "지원 완료" 일정은 상태가 지원 완료일 때만 센다. 다른 상태에서는 빼고, 일정 자체는 지우지 않는다(달력에는 보임). (적용: 이후 전체) (기록: L11)
- D13. 상태 규칙: 같은 상태·세부 단계를 다시 고르면 아무것도 바꾸지 않는다. 자동으로 만드는 일정은 같은 종류·같은 날 일정이 있으면 만들지 않는다. 과제 세부 단계에서 고른 날짜는 "과제 마감" 일정이 된다. (적용: 이후 전체) (기록: L11)
- D14. 일정 추가는 reducer의 `add-event` 동작을 쓰고, 일정 고치기·지우기도 같은 방식(카드 id + 일정, 시각은 보내는 쪽에서)으로 reducer 동작을 추가한다. (적용: 6단계) (기록: L11)
- D15. 일정 고치기: 목록 줄을 펼친 동안 달력 날짜를 누르면 그 일정의 날짜가 바뀌고, 종류 버튼을 누르면 추가 모드로 돌아간다. 메모는 칸을 떠날 때·Enter·창 닫기 때 저장한다(한글 입력 보호). 시간은 브라우저 기본 시간 칸을 쓴다. 일정 ✕ 삭제는 확인 창 없이 바로 지운다. (적용: 이후 전체) (기록: L12)
- D16. 📅 옆에는 전형 일정만 보여준다. `getNextItem`에 마감일 속성 대신 null을 넘겨 마감일은 넣지 않는다 (카드는 그대로 마감일 포함). (적용: 이후 전체) (기록: L12)
- D17. 본문 이미지: 본문(마크다운)에는 `images/파일명` 상대 경로만 적고, 그릴 때 `features/applications/images.ts`의 `resolveImageSrc`로 asset 주소로 바꾼다. 편집기는 처음 열 때의 본문만 읽으므로 카드가 바뀌면 `key`로 새로 만든다. 본문 링크는 클릭으로 열지 않는다(앱 창이 넘어가는 것 방지). (적용: 이후 전체) (기록: L13)
- D18. 큰 달력의 일정은 `features/applications/calendarEntries.ts`의 `groupEntriesByDate`로 모은다(전형 일정 + 지원 준비 카드의 마감일). 한 칸에 3개가 넘으면 2개와 "+N개 더"를 보이고, 누르면 그날 일정 전체를 `Popover`로 보여준다. (적용: 이후 전체) (기록: L14)

# L04 · 2026-11-10 · 구현 2단계: Rust 업데이트 명령

- 요구사항: R3–R5, R7, R14, R21, R23, R33, R36
- 한 일: 새 `updater/` 모듈(mod·check·install)에 `UpdaterState`, `UpdateError { kind: network|signature, message }`, 명령 `updater_info`·`check_update`·`download_update`(Channel 진행률 `{downloaded, total}`)·`install_update`·`discard_update`를 넣었다. 서명 오류로 보는 플러그인 오류는 `Minisign`·`Base64`·`SignatureUtf8`·`SignedVersionMismatch`·`MissingSignedVersion`(2.14.1 소스로 확인). 플러그인 `download`가 받은 뒤 서명을 확인하고 실패하면 바이트를 주지 않으므로, 성공했을 때만 state에 둔다.
- `app_settings.rs`: `notified_update_version: Option<String>` 필드와 `mark_update_notified(version)`. 파일이 없으면 기본값에서 쓰고, 있는데 읽기·해석에 실패하면 쓰지 않고 오류 (D5). `lib.rs`에 state와 명령 6개 등록, `background/api.ts`의 `AppSettings`에 `notifiedUpdateVersion?`.
- 결정: D6 추가
- 계획과 달라진 점 (자동 진행 중 판단, 사용자 동작 변화 없음, D6): 개발 모드의 `check_update` 오류는 kind `network`로 준다. `check_update`가 다른 버전을 찾거나 새 버전이 없으면 예전 받은 바이트를 버린다. `install_update`가 실패하면 받은 바이트를 버린다 (다시 받게 함).
- 확인: `cargo check` 성공 (경고 없음), `npm run build` 성공. 앱을 띄워 명령을 불러 보지는 않았다.
- 사용자 확인: 대기 (최종 테스트)
- 주요 파일: apps/desktop/src-tauri/src/updater/mod.rs, check.rs, install.rs, src-tauri/src/background/app_settings.rs

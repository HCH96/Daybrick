# L08 · 2026-11-03 · 구현 4단계: 종료·강제 종료 복구, 태스크 감시

- 요구사항: R24, R25 (+ D9, D10)
- 한 일: reducer에 `touch`(lastSeenAt만 지금으로)·`recover`(남은 타이머를 lastSeenAt에서 닫아 기록하고 비움) 동작과 공용 `touchRunning`을 더하고, `finish`의 구간 옮기기를 `finishRunning`으로 묶었다. `useHeartbeat`(1분마다 touch), `useTimerGuard`(실행 중 태스크가 진행 중에서 완료·시작 전으로 바뀌거나 지워지면 기록만 하고 타이머 끔)를 새로 만들었다. store는 투데이 데이터가 준비되고 플랜이 읽기를 마치면 한 번 복구하고(태스크가 있고 완료가 아니면 시작 전으로, 플랜 읽기 실패면 기록만), `useTodayAutoSave`의 창 닫기 처리에서 lastSeenAt을 지금으로 적어 바로 저장한다.
- 결정: D13 추가
- 계획과 달라진 점: 복구가 끝나기 전에는 1분 확인·창 닫기 기록·감시를 하지 않게 `recovered` 표시를 두었고, 감시는 "진행 중이었다가 바뀐 때"만 끝으로 본다(시작 직후 플랜 상태가 아직 todo인 순간을 오해하지 않게). Rust는 고치지 않아 `cargo check`는 하지 않았다 (자동 진행 중 판단)
- 확인: `npm run build` 성공 (타입 검사 포함). Node로 reducer 실행: 구간 10:00·lastSeenAt 10:07 → 7분 기록·running 비움, 일시정지(10:00~10:05, lastSeenAt 10:30) → 5분만, lastSeenAt이 열린 구간 시작보다 이르면 그 구간 버림, touch → lastSeenAt 갱신

# L05 · 2026-11-02 · 구현 2단계: 카테고리

- 요구사항: R6–R10
- 한 일: reducer·store에 카테고리 추가·고치기·순서 바꾸기·삭제(안의 태스크는 미분류로, 접힘 목록에서도 뺌)와 최근 쓴 색 넣기(중복 제거, 최대 8개)를 더했다. `color.ts`(hex↔hsv, 색 값 검사·정리)를 만들었다. 왼쪽 목록에 카테고리 묶음 머리(`GroupHead`·`CategoryGroup`), `…` 메뉴(`CategoryMenu`), 만들기·고치기 창(`CategoryForm`, Popover 300px), 자유 색 선택기(`ColorPicker`: 평면·막대 포인터 끌기, 잘못된 색 값은 빨간 테두리), 삭제 확인 창, `+ 카테고리 추가`를 붙였다. `useReorder`(4px 넘게 움직이면 끌기, 놓일 자리 줄, 끈 뒤 클릭 한 번 막기, Esc로 취소)로 카테고리 머리를 끌어 순서를 바꾼다. 미분류 묶음은 미분류 태스크가 있을 때만 보인다(지금은 태스크가 없어 늘 숨김).
- 계획과 달라진 점: 메뉴의 연필 아이콘과 끌 때의 손잡이 아이콘을 `components/icons/CommonIcons.tsx`에 `PenIcon`·`GripIcon`으로 더했다 (자동 진행 중 판단). 묶음 머리의 `+`는 3단계 전까지 눌리지 않게 두었다.
- 확인: `npm run build` 성공 (tsc 포함). Node(`--experimental-strip-types`)로 `#6C5CE7` → hsv → `#6C5CE7` 왕복 확인, 그 밖 hex 약 1만7천 개 왕복도 모두 같음. 화면은 띄워 보지 않음.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 색 값 칸에 `#` 없이 적어도(예: `6c5ce7`) 적용되고, 칸을 벗어나면 마지막 올바른 색으로 돌아오는지 확인. 카테고리 이름이 길면 머리에서 말줄임 되는지 확인.

# 플랜: 결정 사항

- D1. Calendar 메뉴 자리를 Plan으로 바꾸고, Scheduler 메뉴는 그대로 둔다. (적용: 이후 전체) (기록: L01)
- D2. 여러 날 태스크는 연속 기간(시작일~끝일) 하나만 가진다. (적용: 이후 전체) (기록: L01)
- D3. 주간 달력은 시간대 없이 날짜 칸만 둔다. (적용: 이후 전체) (기록: L01)
- D4. 태스크·카테고리는 PC 안 JSON 파일에 저장한다. (적용: 이후 전체) (기록: L01)
- D5. 카테고리를 지우면 그 안의 태스크는 미분류로 옮긴다. (적용: 이후 전체) (기록: L01)
- D6. 주는 월요일에 시작한다. (적용: 이후 전체) (기록: L01)
- D7. 완료한 태스크는 왼쪽 목록에서 카테고리 아래에 접어 둔다. (적용: 이후 전체) (기록: L01)
- D8. 지원관리 일정은 보기 전용이며, 누르면 지원관리 상세 팝업을 연다. (적용: 이후 전체) (기록: L01)
- D9. 카테고리 색은 색 선택기로 자유롭게 고른다. (적용: 이후 전체) (기록: L01)
- D10. 플랜 데이터는 앱 데이터 폴더의 `plan.json` 하나에 두고(Rust `load_plan`/`save_plan`, 0.5초 자동 저장), 화면 설정(접힌 묶음·지원 일정 보이기·최근 쓴 색)도 같은 파일 `view` 칸에 둔다. (적용: 이후 전체) (기록: L03)
- D11. 메뉴 id `calendar`를 `plan`으로 바꾼다. 홈 "오늘 할 일" 카드는 이동할 곳만 `plan`으로 고친다. (적용: 이후 전체) (기록: L03)
- D12. 끌기(목록→달력, 막대 옮기기·끝 끌기, 순서 바꾸기)는 포인터 이벤트로 직접 만든다. 4px 넘게 움직이면 끌기, 아니면 클릭으로 본다. (적용: 2, 6, 8단계 / 이후 전체) (기록: L03)
- D13. 상태 표시를 누르면 시작 전 → 진행 중 → 완료 → 시작 전으로 돈다. 완료가 되면 완료한 날을 기록하고, 완료에서 벗어나면 지운다. (적용: 이후 전체) (기록: L03)
- D14. 없어진 지원 카드를 가리키는 연결은 지원 데이터와 플랜 데이터를 둘 다 다 읽었을 때만 지운다. 읽는 중·읽기 실패면 건드리지 않는다. (적용: 9단계 / 이후 전체) (기록: L03)
- D15. 카테고리와 체크리스트 항목의 순서는 배열 순서로 저장한다 (따로 순서 칸 없음). (적용: 이후 전체) (기록: L03)
- D16. 지원 일정이나 연결 카드를 누르면 페이지를 옮기지 않고 플랜 화면 위에 지원관리 상세 팝업(`ApplicationDetailModal`)을 띄운다. (적용: 7, 9단계 / 이후 전체) (기록: L03)
- D17. 기간을 고쳐 시작일이 끝일보다 뒤가 되면 방금 고르지 않은 쪽을 고른 날로 맞춘다. 날짜 없는 태스크에서 시작일을 고르면 끝일도 같은 날이 된다. (적용: 4단계 / 이후 전체) (기록: L03)
- D18. `NavIcons.tsx`의 `CalendarIcon`은 구직 관리 일정 제안 창이 쓰므로 남겨 두고, 플랜 메뉴는 따로 만든 `PlanIcon`을 쓴다. (적용: 이후 전체) (기록: L04)
- D19. 묶음 머리 아래(바로 적기 입력칸·태스크 줄·"완료 N개")는 `list/GroupTasks.tsx` 하나를 카테고리 묶음과 미분류 묶음이 같이 쓰고, 상태 표시 CSS는 `pages/plan/StatusDot.css`에 둔다(목록·막대·팝업 공용). 미분류 키 `"none"`은 `selectors.ts`의 `NONE_GROUP_KEY`를 쓴다. (적용: 이후 전체) (기록: L06)
- D20. 플랜 상세 팝업은 공용 `Modal`에 `className`(`.modal.task-detail`)을 붙이고 크기는 `Modal` 기본(760×760)을 쓰며, 저장 표시는 `SaveStateLabel`의 `savedLabel="자동 저장됨"`을 팝업 머리 오른쪽(삭제·닫기 앞)에 두고 아래쪽 저장 표시는 없다. 카테고리 고르기 줄은 `pages/plan/CategoryOption.tsx`, 미분류 점 색은 `features/plan/color.ts`의 `NONE_CATEGORY_COLOR`를 같이 쓴다. 팝업 속성 줄 모양은 `detail/TaskDetailModal.css`의 `task-detail__` 클래스(한 줄 `task-detail__prop`(이름 150px + `task-detail__val`), 카테고리 칩 `task-detail__cat`, 글자 값 버튼 `task-detail__plain`, 마우스를 올린 줄에서만 보이는 버튼 `task-detail__hint`, 더하기 버튼 `task-detail__add`)를 쓰고, 최대화 중엔 상자에 `task-detail--max`가 붙는다. (적용: 이후 전체) (기록: L07) (L17에서 변경) (L20에서 변경) (L21에서 변경)
- D21. 주 이동 줄 `WeekNav`(기간·주 이동·`지원 일정` 스위치)는 `PlanPage` 머리의 제목 오른쪽에 두고, `calendar/WeekCalendar`는 요일 머리·몸통을 그린다. 막대 자리는 `features/plan/weekLayout.ts`의 `layoutWeekBars`(`WeekBar`: col·span·lane·cutLeft·cutRight)로 정하고, 달력 클래스(`plan-days`·`plan-cols`·`plan-bars`·`plan-tbar`·`plan-tbar--cut-l/-r`)는 `calendar/WeekCalendar.css`에 둔다. 세로줄 `<i data-day="YYYY-MM-DD">`가 날짜 칸 위치다. 달력 바로 만들기 칸은 `InlineTaskInput`의 `className="plan-task--bar"`로 막대 모양을 낸다. (적용: 6~8단계 / 이후 전체) (기록: L08) (L17에서 변경)
- D22. 끌어 놓기 상태·시작 함수는 `drag/usePlanDrag.ts`의 `PlanDragContext`(`drag`·`startDrag(e, kind, taskId)`)에 두고, `PlanPage`가 `drag/PlanDragProvider`로 목록·달력을 감싼다. 놓을 곳은 `.plan-week`의 `data-drop="calendar"`(날짜는 `.plan-cols` 사각형을 7칸으로 나눈 x 위치)와 `.plan-list`의 `data-drop="list"`(막대 옮기기만 받음, 날짜 지우기), 묶음의 `data-drop-group="<id|none>"`(목록 줄 끌기만 받음, 카테고리 바꾸기)다. 끌 수 없는 것(지원 일정 알약 등)은 `startDrag`를 부르지 않으면 된다. 막대 손잡이·점선·들어 올린 모습 클래스(`plan-tbar__h`·`plan-tbar--ghost/--lift/--sel`)와 놓일 칸(`plan-cols__drop`)·알약(`plan-drop-hint`)은 `drag/drag.css`에, 알약 글자는 `features/plan/format.ts`의 `formatDropHint`에 둔다. (적용: 7~8단계 / 이후 전체) (기록: L09) (L17에서 변경)
- D23. 플랜 달력의 지원 일정은 `features/plan/applicationEvents.ts`의 `buildWeekSchedule(지원 데이터, weekStart)`가 7칸 알약 목록(`SchedPillData`)으로 만들고(일정 고르기는 지원관리 `groupEntriesByDate` 재사용, `CalendarEntry.kind` 추가), `WeekCalendar`가 `.plan-wk-inner` 안 막대 층 위에 `SchedLayer`로 그린다. 스위치가 꺼졌거나 지원 데이터가 준비되지 않았거나 이번 주에 일정이 없으면 층을 그리지 않는다. 알약·풍선·스위치 클래스(`plan-sched`·`plan-ev`·`plan-ev--deadline/--task/--coding/--interview`·`plan-ev-tip`·`plan-switch`)는 `calendar/WeekCalendar.css`에 두고, 풍선은 body 포털로 띄운다. 스위치는 페이지 머리 `WeekNav` 안에 있고 store의 `setShowApplicationEvents`, 지원 상세 팝업은 `PlanPage`의 `openApplicationId`(WeekCalendar `onOpenApplication`)다. (적용: 9단계 / 이후 전체) (기록: L10) (L17에서 변경)
- D24. 체크리스트 진행도(완료 수/전체)는 `features/plan/selectors.ts`의 `checklistProgress(task)`로 구하고, 항목이 0개면 목록 줄·막대에 보이지 않는다. 팝업 체크리스트는 `PropRows`의 마지막 "체크리스트" 줄(`+ 체크리스트` 또는 진행도 `task-check__count`·막대 `task-check__mini`)과 그 아래 항목 목록 `detail/Checklist`(체크리스트가 없으면 아무것도 그리지 않고, 막 만들어지면 빈 항목 하나로 시작)·`ChecklistItemRow`, 클래스는 `detail/Checklist.css`의 `task-check__`이고, 항목 끌기는 `useReorder(count, onMove, { follow: true })`의 `dragOffset`으로 띄운 항목(`task-check__item--lift`)을 옮기며 원래 자리는 `task-check__item--gap`이다(카테고리는 옵션 없이 부른다). 목록 줄 진행도는 `plan-task__prog`(TaskList.css), 막대 진행도는 `plan-tbar__meta`(WeekCalendar.css, 잘린 쪽 › 앞)다. store 체크리스트 함수는 `createChecklist`·`deleteChecklist`·`addCheckItem(taskId, index)`(빈 항목 id 반환)·`updateCheckItem`·`deleteCheckItem`·`moveCheckItem`이다. (적용: 9단계 / 이후 전체) (기록: L11) (L17에서 변경) (L21에서 변경)
- D25. 지원 카드 연결은 store `linkApplication(taskId, id|null)`로 하고, 없어진 카드 연결 정리는 `features/plan/useLinkCleanup.ts`가 `PlanProvider` 안에서 `clear-missing-links`를 직접 보낸다(ApplicationsProvider가 PlanProvider 바깥이어야 함). 카드 표시용 순수 함수(`findLinkCard`·`buildCardPickList`·`LinkCardItem`)는 `features/plan/applicationLinks.ts`, 회사 이름은 `applicationEvents.ts`의 `companyName`이다. 팝업 줄은 `detail/LinkedCardRow`·고르기 창은 `detail/CardPickDialog`(Popover, 클래스 `card-pick__`·`task-card-link__`는 `CardPickDialog.css`), 목록 줄 연결 회사는 `plan-task__lnk`(TaskList.css), 아이콘은 `PlanIcons.tsx`의 `LinkIcon`·`SearchIcon`이다. (적용: 이후 전체) (기록: L12)
- D26. 태스크 팝업의 정리 칸 이름은 `Notes`로 한다. 화면 제목 `Plan`, 머리 글자 `Task`처럼 플랜 화면의 이름표는 영어로 쓴다. (적용: 이후 전체) (기록: L15)
- D27. r1 디자인 수정(기간 표시, 요일 머리, 완료 표시, 팝업, 휴지통, 끄는 모습)은 /mockup으로 안을 보고 정한 뒤 계획을 세운다. 폰트는 전역 변경 때로 미룬다. (적용: 이후 전체) (기록: L15)
- D28. 앱 최소 창 크기 960×640은 바꾸지 않는다. 창 크기 문제는 플랜 화면 배치로 해결한다. (적용: 이후 전체) (기록: L15)
- D29. 페이지 머리 기간 표시의 주 번호는 ISO 주(월요일 시작)로 센다 (`utils/date.ts` `isoWeekNumber`, 2026-11-02 주 = `Week 45`). 기간 글자는 `features/plan/format.ts` `formatWeekTitle`. (적용: 1단계 / 이후 전체) (기록: L17)
- D30. 플랜 화면 배치는 `grid-template-columns: minmax(200px, 2fr) 5fr`로 목록·달력이 같은 비율로 줄고, 좁은 창 대응은 CSS로만 한다. (적용: 1단계 / 이후 전체) (기록: L17)
- D31. 달력 막대를 목록에 놓으면 날짜만 지우고(R27) 카테고리는 바꾸지 않는다. 카테고리 옮기기(R45)는 목록 줄 끌기만 한다. 같은 묶음에 놓으면 아무것도 바꾸지 않는다. (적용: 6단계 / 이후 전체) (기록: L17)
- D32. 태스크 메모 저장 칸 이름은 `memo` 그대로 두고 화면 이름만 `Notes`로 한다. 저장 파일 옮기기는 하지 않는다. (적용: 이후 전체) (기록: L17)
- D33. 플랜 화면 제목은 `app/pageLabels.ts`의 `NAV_LABELS.plan`(`Plan`)을 쓰고, `PAGE_LABELS.plan`은 홈 카드 버튼("플랜으로 가기")·알림 출처가 쓰는 한글 이름 `플랜` 그대로 둔다. 좁은 창 대응은 이름 붙은 컨테이너 쿼리로 한다: 달력 `.plan-week`(`plan-week`, 620px 이하)·빠른 입력 `.plan-quick`(`plan-quick`, 260px 이하). (적용: 이후 전체) (기록: L18)

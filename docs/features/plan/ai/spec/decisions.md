# 플랜: 결정 사항

- D1. Calendar 메뉴 자리를 Plan으로 바꾸고, Scheduler 메뉴는 그대로 둔다. (적용: 이후 전체) (기록: L01)
- D2. 여러 날 태스크는 연속 기간(시작일~끝일) 하나만 가진다. (적용: 이후 전체) (기록: L01)
- D3. 주간 달력은 시간대 없이 날짜 칸만 둔다. (적용: 이후 전체) (기록: L01)
- D4. 태스크·카테고리는 PC 안 JSON 파일에 저장한다. (적용: 이후 전체) (기록: L01)
- D5. 카테고리를 지우면 그 안의 태스크는 미분류로 옮긴다. (적용: 이후 전체) (기록: L01)
- D6. 주는 월요일에 시작한다. (적용: 이후 전체) (기록: L01)
- D7. 완료한 태스크는 왼쪽 목록에서 카테고리 아래에 접어 둔다. (적용: 이후 전체) (기록: L01)
- D8. 지원관리 일정은 보기 전용이며, 누르면 지원관리 상세 팝업을 연다. (적용: 이후 전체) (기록: L01)
- D9. 카테고리 색은 색 선택기로 자유롭게 고른다. (적용: 이후 전체) (기록: L01)
- D10. 플랜 데이터는 앱 데이터 폴더의 `plan.json` 하나에 두고(Rust `load_plan`/`save_plan`, 0.5초 자동 저장), 화면 설정(접힌 묶음·지원 일정 보이기·최근 쓴 색)도 같은 파일 `view` 칸에 둔다. (적용: 이후 전체) (기록: L03)
- D11. 메뉴 id `calendar`를 `plan`으로 바꾼다. 홈 "오늘 할 일" 카드는 이동할 곳만 `plan`으로 고친다. (적용: 이후 전체) (기록: L03)
- D12. 끌기(목록→달력, 막대 옮기기·끝 끌기, 순서 바꾸기)는 포인터 이벤트로 직접 만든다. 4px 넘게 움직이면 끌기, 아니면 클릭으로 본다. (적용: 2, 6, 8단계 / 이후 전체) (기록: L03)
- D13. 상태 표시를 누르면 시작 전 → 진행 중 → 완료 → 시작 전으로 돈다. 완료가 되면 완료한 날을 기록하고, 완료에서 벗어나면 지운다. (적용: 이후 전체) (기록: L03)
- D14. 없어진 지원 카드를 가리키는 연결은 지원 데이터와 플랜 데이터를 둘 다 다 읽었을 때만 지운다. 읽는 중·읽기 실패면 건드리지 않는다. (적용: 9단계 / 이후 전체) (기록: L03)
- D15. 카테고리와 체크리스트 항목의 순서는 배열 순서로 저장한다 (따로 순서 칸 없음). (적용: 이후 전체) (기록: L03)
- D16. 지원 일정이나 연결 카드를 누르면 페이지를 옮기지 않고 플랜 화면 위에 지원관리 상세 팝업(`ApplicationDetailModal`)을 띄운다. (적용: 7, 9단계 / 이후 전체) (기록: L03)
- D17. 기간을 고쳐 시작일이 끝일보다 뒤가 되면 방금 고르지 않은 쪽을 고른 날로 맞춘다. 날짜 없는 태스크에서 시작일을 고르면 끝일도 같은 날이 된다. (적용: 4단계 / 이후 전체) (기록: L03)
- D18. `NavIcons.tsx`의 `CalendarIcon`은 구직 관리 일정 제안 창이 쓰므로 남겨 두고, 플랜 메뉴는 따로 만든 `PlanIcon`을 쓴다. (적용: 이후 전체) (기록: L04)
- D19. 묶음 머리 아래(바로 적기 입력칸·태스크 줄·"완료 N개")는 `list/GroupTasks.tsx` 하나를 카테고리 묶음과 미분류 묶음이 같이 쓰고, 상태 표시 CSS는 `pages/plan/StatusDot.css`에 둔다(목록·막대·팝업 공용). 미분류 키 `"none"`은 `selectors.ts`의 `NONE_GROUP_KEY`를 쓴다. (적용: 이후 전체) (기록: L06)
- D20. 플랜 상세 팝업은 공용 `Modal`의 `className`으로 크기를 정하고(`.modal.task-detail`), 저장 표시는 `SaveStateLabel`의 `savedLabel="자동 저장됨"`을 쓴다. 카테고리 고르기 줄은 `pages/plan/CategoryOption.tsx`, 미분류 점 색은 `features/plan/color.ts`의 `NONE_CATEGORY_COLOR`를 같이 쓴다. 팝업 속성 줄 모양은 `detail/TaskDetailModal.css`의 `task-detail__` 클래스(칩 `task-detail__chip`, 글자 버튼 `task-detail__txt-btn`)를 쓴다. (적용: 이후 전체) (기록: L07)
- D21. 주 이동 줄 `WeekNav`는 `PlanPage`에 두고 그 아래 `calendar/WeekCalendar`가 요일 머리·몸통을 그린다. 막대 자리는 `features/plan/weekLayout.ts`의 `layoutWeekBars`(`WeekBar`: col·span·lane·cutLeft·cutRight)로 정하고, 달력 클래스(`plan-days`·`plan-cols`·`plan-bars`·`plan-tbar`·`plan-tbar--cut-l/-r`)는 `calendar/WeekCalendar.css`에 둔다. 세로줄 `<i data-day="YYYY-MM-DD">`가 날짜 칸 위치다. 달력 바로 만들기 칸은 `InlineTaskInput`의 `className="plan-task--bar"`로 막대 모양을 낸다. (적용: 6~8단계 / 이후 전체) (기록: L08)
- D22. 끌어 놓기 상태·시작 함수는 `drag/usePlanDrag.ts`의 `PlanDragContext`(`drag`·`startDrag(e, kind, taskId)`)에 두고, `PlanPage`가 `drag/PlanDragProvider`로 목록·달력을 감싼다. 놓을 곳은 `.plan-week`의 `data-drop="calendar"`(날짜는 `.plan-cols` 사각형을 7칸으로 나눈 x 위치)와 `.plan-list`의 `data-drop="list"`(막대 옮기기만 받음)다. 끌 수 없는 것(지원 일정 알약 등)은 `startDrag`를 부르지 않으면 된다. 막대 손잡이·점선·들어 올린 모습 클래스(`plan-tbar__h`·`plan-tbar--ghost/--lift/--sel`)와 놓일 칸(`plan-cols__drop`)·알약(`plan-drop-hint`)은 `drag/drag.css`에, 알약 글자는 `features/plan/format.ts`의 `formatDropHint`에 둔다. (적용: 7~8단계 / 이후 전체) (기록: L09)
- D23. 플랜 달력의 지원 일정은 `features/plan/applicationEvents.ts`의 `buildWeekSchedule(지원 데이터, weekStart)`가 7칸 알약 목록(`SchedPillData`)으로 만들고(일정 고르기는 지원관리 `groupEntriesByDate` 재사용, `CalendarEntry.kind` 추가), `WeekCalendar`가 `.plan-wk-inner` 안 막대 층 위에 `SchedLayer`로 그린다. 스위치가 꺼졌거나 지원 데이터가 준비되지 않았거나 이번 주에 일정이 없으면 층을 그리지 않는다. 알약·풍선·스위치 클래스(`plan-sched`·`plan-ev`·`plan-ev--deadline/--task/--coding/--interview`·`plan-ev-tip`·`plan-switch`)는 `calendar/WeekCalendar.css`에 두고, 풍선은 body 포털로 띄운다. 스위치는 store의 `setShowApplicationEvents`, 지원 상세 팝업은 `PlanPage`의 `openApplicationId`(WeekCalendar `onOpenApplication`)다. (적용: 9단계 / 이후 전체) (기록: L10)
- D24. 체크리스트 진행도(완료 수/전체)는 `features/plan/selectors.ts`의 `checklistProgress(task)`로 구하고, 항목이 0개면 목록 줄·막대에 보이지 않는다. 팝업 체크리스트는 `detail/Checklist`(메모 위)·`ChecklistItemRow`, 클래스는 `detail/Checklist.css`의 `task-check__`이고, 목록 줄 진행도는 `plan-task__prog`(TaskList.css), 막대 진행도는 `plan-tbar__meta`(WeekCalendar.css, 잘린 쪽 › 앞)다. store 체크리스트 함수는 `createChecklist`·`deleteChecklist`·`addCheckItem(taskId, index)`(빈 항목 id 반환)·`updateCheckItem`·`deleteCheckItem`·`moveCheckItem`이다. (적용: 9단계 / 이후 전체) (기록: L11)
- D25. 지원 카드 연결은 store `linkApplication(taskId, id|null)`로 하고, 없어진 카드 연결 정리는 `features/plan/useLinkCleanup.ts`가 `PlanProvider` 안에서 `clear-missing-links`를 직접 보낸다(ApplicationsProvider가 PlanProvider 바깥이어야 함). 카드 표시용 순수 함수(`findLinkCard`·`buildCardPickList`·`LinkCardItem`)는 `features/plan/applicationLinks.ts`, 회사 이름은 `applicationEvents.ts`의 `companyName`이다. 팝업 줄은 `detail/LinkedCardRow`·고르기 창은 `detail/CardPickDialog`(Popover, 클래스 `card-pick__`·`task-card-link__`는 `CardPickDialog.css`), 목록 줄 연결 회사는 `plan-task__lnk`(TaskList.css), 아이콘은 `PlanIcons.tsx`의 `LinkIcon`·`SearchIcon`이다. (적용: 이후 전체) (기록: L12)

# 서버 연결 요구사항: 서버 구조 갱신 (R20–R27)

### 서버 구조 번호
- R20. 서버에 서버 구조 번호와 적용 기록(번호, 적용 시각, 적용한 앱 버전)을 둔다.
- R21. 앱은 서버 구조 단계(1번, 2번…)마다 바꾸는 내용(SQL, 서버 함수)을 앱 안에 가지고 있다.
- R22. 자동 세팅은 0번부터 최신 번호까지, 서버 업데이트는 현재 번호 다음부터 최신 번호까지 차례로 적용한다.
- R23. 접속 확인 때 서버 번호가 앱보다 낮으면 "서버 업데이트 필요"를 알린다. 사용자가 PAT를 넣고 [업데이트]를 누르면 빠진 단계를 적용하고 PAT를 버린다. 진행 표시와 실패 처리는 R15·R17과 같다.
- R24. 서버 번호가 앱보다 높으면 "앱을 업데이트하세요"라고 안내하고 서버 기능을 쓰지 않는다.
- R25. 서버 업데이트가 끝날 때까지 서버 기능은 막고, 로컬 기능은 그대로 쓴다.
- R26. 단계 하나는 한 묶음으로 적용한다. 중간에 실패하면 그 단계는 적용 전 상태로 되돌리고, 번호는 성공한 단계까지만 올린다.
- R27. 이후 기능(notifications, job-search 등)은 자기 서버 구조를 새 번호의 단계로 추가하고, 이미 배포한 단계의 내용은 고치지 않는다.

이번 기능이 만드는 1번 단계: 구조 기록 테이블, 서버 상태 테이블(Anthropic 키 등록일 등), 접속 확인 함수, AI 키 확인 함수. 자세한 항목은 [data.md](data.md).

### 예시 (이해용)
1. 앱 1.0으로 자동 세팅 → 서버 번호 1.
2. 구직 관리가 들어간 앱 2.0은 2번 단계(공고·프로필 테이블 등)를 가지고 있다.
3. 사용자가 앱을 2.0으로 바꾸면 접속 확인에서 "서버 1 < 앱 2"를 감지하고 서버 업데이트를 안내한다.
4. PAT를 넣고 [업데이트] → 2번 단계 적용 → 서버 번호 2.

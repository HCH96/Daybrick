# L07 · 2026-11-08 · 구현 5단계: 자동 올리기

- 요구사항: R9–R12, R14, R24, R26, R30
- 한 일: 기능 useAutoSave 4개가 저장 성공 뒤 `notifySaved(kind)`를 부른다. 새 `features/sync/useUploadQueue.ts`(대기 표시를 sync.json에 저장 → 5초 타이머 → 한 종류씩 readLocal·해시 비교·빈 데이터 검사·`pushDoc(baseRev = last.rev)`, 충돌은 "선택 필요", network·auth는 "대기"+오류 문구, 한 번에 하나씩 돌고 도는 중 호출은 끝난 뒤 한 번 더).
  새 `useCloseFlush.ts`(창 닫기 때 로컬 저장 ≤1초 → 올리기 ≤3초). `SyncProvider`가 둘을 쓰고 `uploadNow`·`uploading`·`closeFlush`를 컨텍스트로 내보낸다(`failed`·`deviceName`은 useUploadQueue.ts로 옮김). 설정 칸에 [지금 올리기] 줄(대기 없으면 흐림).
- 결정: D13 추가
- 계획과 달라진 점: (자동 진행 중 판단) 닫기 순서를 보니 Tauri `onCloseRequested` 처리기는 각자 끝나는 대로 창을 없애므로, 동기화 처리기를 따로 두지 않고 기능 닫기 처리기가 `closeFlush(로컬 저장)`을 기다리게 했다. 그래서 step에 없는 `features/notifications/useAutoSave.ts`도 같은 방식으로 고쳤다(먼저 닫아 버리지 않게). sync.json 쓰기를 차례대로 하도록 `commit`을 고쳤다. 꺼져 있을 때는 대기를 남기지 않는다(다시 켜면 켜기 흐름이 비교, R27).
- 확인: `npm run build` 성공 (타입 검사 포함). 실제 서버로 올리기·닫기 흐름은 돌려 보지 않음.
- 사용자 확인: 대기 (최종 테스트)
- 테스트 메모: 창 닫기는 최대 약 4초 늦어질 수 있다(로컬 1초 + 올리기 3초, 보통은 바로). 플랜 태스크를 모두 지워 빈 데이터가 되면 서버에 올리지 않고 "선택 필요"가 된다(R15).

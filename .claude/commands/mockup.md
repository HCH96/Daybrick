"$ARGUMENTS"의 목업을 만들어줘.
관련 명세서가 docs/ai/features 아래에 있으면 먼저 읽고 참고해줘.

- 디자인 확인용이니까 기능이나 동작은 구현하지 말고, 화면 배치와 스타일만 보여주는 정적 화면으로 만들어줘.
- 데이터는 실제처럼 보이는 예시 값으로 채워줘.
- 브라우저에서 바로 열 수 있는 HTML 파일 하나로 만들어 docs/human/mockups/에 저장하고, 파일 경로를 알려줘.
- 목업은 기능당 한 파일로 관리한다. 같은 기능의 화면을 추가할 때는 새 파일을 만들지 말고 그 기능의 목업에 구역을 추가한다.
  (색·배치 후보를 비교하는 목업은 예외로 별도 파일을 만들 수 있다.)

## 구역 ID 규칙
AI가 목업 전체를 읽지 않고 필요한 구역만 찾아 읽을 수 있게, 아래 규칙을 반드시 지킨다.

- 화면(또는 비교 후보) 하나마다 `<section id="화면ID">`로 감싼다.
- 한 화면 안에 따로 구현될 수 있는 부분(작은 창, 카드 등)이 여럿이면 각각 `id="화면ID-부분ID"`를 붙인다.
  예: `parts` 화면 안의 상태 선택 창 → `id="parts-status"`
- ID는 영어 소문자·숫자·하이픈만 쓰고, 파일 안에서 겹치지 않게 한다.
- 화면 제목 옆과 목차에 관련 요구사항 번호(R)를 적는다.
- 한 번 정한 ID는 되도록 바꾸지 않는다. 바꾸거나 지우면 docs/ 아래에서 그 ID를 참조하는 곳을 찾아 함께 고친다.

## 목업 목차
`<!DOCTYPE html>` 바로 다음 줄(`<style>`보다 위)에 목차 주석을 둔다. 형식:

```html
<!-- 목업 목차: <기능 이름>
  ID               화면                         요구사항
  gallery          1. 갤러리 (기본 화면)          R1–R6
  parts            5. 작은 창 모음                 -
  parts-status       5-1. 상태 선택              R18–R19
-->
```

- 구역 ID를 추가·삭제·변경하면 목차도 같은 작업에서 고친다.
- 목차에는 모든 화면 ID와 부분 ID를 빠짐없이 적는다. 부분 ID는 들여쓴다.

내가 목업을 승인하면 다음을 해줘.
- 해당 기능 명세서의 "## 목업" 절에 목업 경로(승인 날짜)와 "목업에서 정한 것"을 기록
- DOCS_INDEX.md에 경로와 한 줄 설명을 추가 (구역별 설명은 목업 목차에만 두고 DOCS_INDEX에는 적지 않는다)
- 진행 기록 파일에 "목업" 항목을 남기기 (/implement 명령의 "진행 기록 쓰는 법". 기록 파일이 아직 없으면 만든다)

"$ARGUMENTS" 기능의 구현이 끝났어. 아래 순서대로 테스트를 진행해줘.

## 0. 테스트 계획
테스트를 수행하기 전에 아래 문서를 읽고 테스트 계획을 세워줘.
- docs/ai/features 아래의 "$ARGUMENTS" 기능 명세서
- docs/ai/plans 아래의 "$ARGUMENTS" 구현 계획 문서
- docs/ai/logs 아래의 "$ARGUMENTS" 최신 기록 파일의 목차 (계획과 달라진 점이 있는 항목 등 필요한 항목만 읽기)
- 목업이 필요하면 맨 앞 목업 목차만 읽고, 필요한 ID 구역과 그 구역의 CSS 클래스만 검색해서 읽기

문서를 찾지 못하면 테스트를 진행하지 말고 나에게 알려줘.

계획을 세울 때 다음을 기준으로 해줘.
- 명세서의 요구사항마다 최소 하나 이상의 테스트 항목을 만든다.
- 구현 계획의 단계별 "확인할 결과"도 테스트 항목에 반영한다.
- 정상 동작뿐 아니라 경계 상황과 예외 상황도 포함한다.
  (예: 빈 데이터, 잘못된 입력, 앱 재시작 후 데이터 유지)
- 명세서에서 "이번 범위에서 제외"한 기능은 테스트하지 않는다.
- 각 항목을 AI 테스트와 사용자 테스트 중 어디에 넣을지 나눈다.

계획을 표로 보여줘. 표에는 테스트 항목, 근거가 되는 요구사항, 테스트 주체(AI / 사용자)를 넣어줘.
내가 승인하면 1번과 2번을 진행해줘.

## 1. AI 테스트 보고서
승인된 계획 중 AI 테스트 항목을 직접 수행하고,
docs/ai/tests/<기능명>-ai-test.md에 저장해줘.

항목마다 다음을 적어줘.
- 테스트 내용
- 근거 요구사항
- 수행 방법 (실행한 명령어 등)
- 예상 결과
- 실제 결과
- 판정 (통과 / 실패)
- 실패한 경우 원인 추정과 수정 방향

실패한 항목은 바로 고치지 말고, 보고서를 보여준 뒤 수정할지 나에게 물어봐줘.
수행할 테스트가 없으면 없다고 명시해줘.

## 2. 사용자 테스트 체크리스트 (초안)
승인된 계획 중 사용자 테스트 항목을 정리해서
docs/human/tests/<기능명>-user-test.md에 저장해줘.
결과 칸은 내가 직접 채울 거니까 비워 둬.

항목마다 다음 형식으로 적어줘.

### [번호]. 테스트 이름
- 근거 요구사항:
- 수행 방법: 무엇을 어떤 순서로 누르는지
- 예상 결과:
- 확인 위치: 화면 어디를 보면 되는지
- 실제 결과: (사용자 작성)
- 판정: [ ] 통과  [ ] 실패
- 메모: (사용자 작성)

확인할 것이 없으면 없다고 명시해줘.

## 3. 문서 저장 후
- 해당 기능 명세서의 "## 테스트 문서" 절에 두 테스트 문서의 경로를 기록해줘.
- DOCS_INDEX.md에 경로와 한 줄 설명을 추가해줘.
- 진행 기록 파일에 "테스트" 항목을 남겨줘 (/implement 명령의 "진행 기록 쓰는 법"). 사용자 테스트 결과가 나오면 같은 방식으로 한 항목 더 남겨줘.
- 내가 사용자 테스트를 진행할 수 있게 체크리스트 문서 경로를 알려줘.

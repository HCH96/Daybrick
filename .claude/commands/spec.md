아래는 내가 자유롭게 말한 기능 요구사항이야.

$ARGUMENTS

이걸 바탕으로 기능 명세서를 만들어줘.

진행 방식:
1. 먼저 요구사항을 정리해서 보여주고, 빠졌거나 모호한 부분을 질문해줘. 질문은 한 번에 너무 많지 않게, 중요한 것부터 해줘.
2. 내가 정해야 하는 건 네가 마음대로 정하지 말고 질문해줘. 단순한 건 추천안을 함께 보여줘도 돼.
3. 질문이 끝나면 아래 "명세서 양식"대로 초안을 보여줘.

내가 초안을 승인하면:
- docs/ai/features/<기능명>.md로 저장
- 진행 기록 파일 docs/ai/logs/<기능명>-log.md를 만들고 L01 "명세" 항목을 남기기 (/implement 명령의 "진행 기록 쓰는 법")
- PROJECT.md의 기능별 상태 표에 문서 경로를 기록
- DOCS_INDEX.md에 명세서와 기록 파일의 경로·한 줄 설명을 추가

이미 있는 기능의 명세서를 고칠 때는 진행 기록 최신 파일의 목차를 확인하고, 아래 "R 번호 규칙"을 지켜 고친 뒤 고친 내용을 "명세" 항목으로 남겨줘.

아직 코드는 작성하지 마.

## 명세서 양식
절 제목과 순서를 바꾸지 않는다. 다른 문서(기록 목차, 목업 목차, 노트, 계획)가 이 절 이름과 R·D 번호를 참조한다.
아직 채울 내용이 없는 절도 제목은 두고 "(아직 없음)"이라고 적는다.
기능에 꼭 필요한 절(예: 확장 구조, 파일 구조, 창 설정, 완료 기준)은 "나중에 고려할 것"과 "목업" 사이에만 추가한다. 정해진 절의 이름과 순서는 그대로 둔다.

```markdown
# <기능 이름> (<기능명>)

## 기능 개요
한두 줄. 이 기능이 무엇을 왜 하는지.

## 요구사항
### <묶음 이름 (화면이나 기능 단위)>
- R1. 한 문장에 요구사항 하나.
- R2. …
### <다음 묶음>
- R3. …
(표나 보충 설명은 해당 묶음 안, R 줄 아래에 둔다)

## 화면 구성
글이나 간단한 그림으로. 화면마다 관련 R 번호를 적는다.

## 다룰 데이터
항목, 종류, 저장 위치.

## 이번 범위에서 제외하는 것

## 나중에 고려할 것

## 목업
/mockup 명령이 채운다: 목업 경로(승인 날짜), "목업에서 정한 것", 목업에 넣은 추가 제안.

## 구현 계획
/plan 명령이 채운다: 계획 문서 경로(승인 날짜), 계획에서 정한 것 한두 줄.

## 결정 사항
형식: `D번호. 내용 (적용: 계획 단계 범위 또는 "이후 전체") (기록: L번호)`. /implement 명령의 "결정 올리기"를 따른다.

## 테스트 문서
/test 명령이 채운다: AI 테스트 보고서와 사용자 테스트 체크리스트 경로.

## 진행 기록
기록 파일 링크만 둔다. 본문은 docs/ai/logs/<기능명>-log.md에 쓴다.
```

## R 번호 규칙
- 요구사항마다 `R번호.`를 붙인다. 번호는 기능 안에서 R1부터 차례로 붙인다.
- 묶음은 화면이나 기능 단위로 나눈다. 번호는 묶음을 넘어 이어진다.
- 한 번 붙인 번호는 바꾸거나 다시 쓰지 않는다.
  - 요구사항을 새로 넣으면, 들어갈 묶음과 상관없이 지금까지 가장 큰 번호의 다음 번호를 쓴다.
  - 요구사항을 없애면 줄을 지우지 않고 `- ~~R7. 내용~~ (삭제, L번호)`로 남긴다.
  - 내용을 바꾸면 같은 번호를 쓰고 줄 끝에 `(L번호에서 변경)`을 붙인다.
- 다른 문서에서 요구사항을 가리킬 때는 R 번호를 쓴다. 범위는 `R17–R22`처럼 적는다.
